## 進め方の注意

- Codex は使える。作り方・変えてよい期待値・判定の順を先に書いて渡す。止まる決まりは、ゆらぎで超えない幅にする（8回の早送りで決着1つの違いはゆらぎ）。続きを頼む `codex exec resume` には `-c sandbox_mode="danger-full-access"` を付ける（付けないとブラウザが起動できない）。Codex が作った写真の道具は、写真を自分で開いて確かめる（`docs/collaboration.md`）。
- マージは、CI の4つの確認（`smoke (ground)`・`smoke (drill)`・`smoke (npc)`・`smoke (space)`）がすべて成功してから。`gh pr view <番号> --json statusCheckRollup` で結論を見る（`.claude/skills/ship/SKILL.md`）。
- 手元の `npm test` が「実行中に例外」で止まったら、そのあとの分野は走っていない。例外の出た分野と残りの分野（`npm run test:drill` など）を回してから PR にする（2026-11-17: 演習の確かめを見落とし、CI で落ちた。`.claude/skills/ship/SKILL.md`）。
- ブラウザを使うテストと早送りは同時に2つ走らせない。
- `gh pr merge --delete-branch` で作業フォルダが消えることがある。写真は先に別の場所へ写す。
- 本体の作業フォルダ（`~/dev/War-of-space`）の `docs/PROJECT_STATUS.md` と、2026-11-11 の引き継ぎの資料（docs フォルダの CLAUDE_HANDOFF）には、ユーザーの手元だけの版がある。コミットしない。main を取り込むときは `git merge --ff-only origin/main`（`reset --hard` は手元の版を消すので使わない）。取り込む変更がこのファイルに触れて止まったら、手元の版を別の場所へ写してから取り込み、戻す。手元の版は古いことがあるので、main の版（`git show origin/main:docs/PROJECT_STATUS.md`）も読む。
- 写真を持つ Codex の作業フォルダ（`~/dev/wos-codex-ground-integration`・`~/dev/wos-codex-town-plan` など）は消さない。
- リポジトリは公開。ほかの人の絵や写真は入れない（モデルの参考の絵も、見るだけにする）。
- 返事はいつも日本語（`開発環境/CLAUDE.md`。英語になると Stop フックが止める）。
