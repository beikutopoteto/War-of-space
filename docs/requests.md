## 指示の範囲

- **書かれたことだけをやる。** 「他は大丈夫なので〇〇だけ」「〇〇の画面だけ」のように範囲を絞ることが多い。言われていない画面や機能まで広げない。広げたほうがよさそうなときは、範囲を選択肢にして聞く（例: 「縮小」は技術ツリーの画面だけか全体か）。
- **1つのメッセージに複数の頼みが入る。** 「また」「あと」でつながる。全部拾い、話題ごとに PR を分ける。
- **「〇〇も残して」「〇〇は残してください」** は、変える対象から外すもの。忘れずに守る（例: ウィンドウの形を変えても、艦隊の上の国旗アイコンは残す）。
- **「もし今もそうなら実装しなくても良い」** と言われたら、まずコードで今の動きを確かめ、そうなっているなら作らずに報告する。
- **「これからも同じなので仕様に残して」** は、その作戦だけでなく今後すべての決まり。`docs/spec.md` に「これからの作戦もすべて」と書く。
- **「今はとりあえず〇〇して」** は、あとで正式な形（チュートリアルなど）に置き換える前提の仮の実装。資料に「仮」と、置き換え先を書く。
- **「難易度は今と同じぐらい」** は、編成を変えても勝ち負けの時刻や残りの耐久が前と近くなるよう、早送りで確かめて合わせる。

## 質問のしかた

- 曖昧なら、実装の前に選択式で聞く（ユーザーは「あいまいであれば質問してください」と念を押している）。
- **すでにあるものを聞かない。** 「下二つはもうありますよね？」と返されたことがある。聞く前にコードと資料で今の状態を確かめ、ないものだけを聞く。
- **仕様上ありえない場合を聞かない。** 「てか仕様上そうならないのでは？」と返されたことがある。選択肢を作る前に `docs/spec.md` と照らし合わせる。
- 選択肢に合わないとき、ユーザーは自由記述で答える。自由記述の答えは選択肢より優先し、そのまま仕様として扱う。
- 自由記述の欄に、その質問ではなく別の話題の答え（前の案の取り消しなど）を書くことがある（2026-10-09）。書かれた内容は仕様として扱い、答えのなかった質問は「決めてほしいこと」に残す。
- 番号付きで質問すると、ユーザーは「1 〜 2 問題ない」のように番号で答える。「問題ない」はそのまま採用の意味。
- 「〇〇は適当に」は Claude が決めてよいという意味。決めた内容は資料に書き、報告で一言伝える。
- 地形や配置は、世界設定（地球の軌道上か、月より遠いか、など）に照らして自然かを確かめてから出す。「あからさまな隕石帯」「こんなまっすぐですぐ横にあるわけない」と指摘されたことがある（2026-10-09）。決まった艦種でも、物語の時点で開発されていないものは出さない（強襲母艦）。
- 「この二つをうまいこと組み合わせたい」は、選択肢のどれかではなく、前の案と新しい指示を両方生かす案を Claude が考えて書くという意味（2026-10-09、第4節の盾と負けイベント）。案は「決めてほしいこと」に回して確かめる。
- 「わたしの前提について討論しましょう」と番号つきの前提が来たら、作らずに議論する。前提ごとに賛否と理由、今の作りとのずれ（事実）、詰めるべき点を出し、分かれ道を番号つきの選択肢（推しを先頭）で聞く。答えは「1①」「2①と②の両方で〜」の形で来る。「両方」は両方の案を組み合わせる意味（2026-10-20、両陣営の技術と強さ）。
- 「計画はこんなのがイメージです」と両軍の動きの構想が来たら、すぐ作らずに、構想を資料に書き、曖昧な点（向き、何を数えるか、合図）を選択式で聞き、`wos-strategy` に布陣・数・流れの案を出させて見せる（2026-10-28、第6節の陽動）。「左上・右下」は正面から見た向きで、高度も含む（左上＝西の上、右下＝東の下）。
- 「できるだけ基礎の変数は変えないでください」（2026-10-29、第6節の釣り合わせ）: 全作戦で共通の値（艦種の性能、W.A.S. の1隻8機、耐久・打撃の倍率、`data/ships.js` の数）は変えず、その節のデータ（隊の数と内訳、置き場所、出る時刻、動き、その節だけの物の耐久）で合わせる。共通の値を変えるしかないときは、先に聞く。
- 「耐久を調節するとかは許されません」（2026-10-30、ユーザーが Codex に。第4節の作業票 #241）: 釣り合わせで艦の耐久（本軍・敵・その節の隊の `hp` や倍率、傷み `hurt`、回復）を変えない。数・内訳・出る時刻・動き・速さで合わせる。作業票の「届かないとき」にも耐久は入れない。
- 選択式の答えが自由記述で、どの選択肢とも違う短い言い方（例:「陽動はほしいです、一部を戻して」）なら、読める意味を2〜3通りの選択肢にしてもう一度聞く（2026-10-29。答えは「陽動から割いて戻す」だった）。
- 「〇〇のサブエージェントの最適化も」は、`.claude/agents/*.md` に、ユーザーの好む作戦や動き（陽動、引きずり出し、段階の切り替えなど）が出やすくなる指針を足すという意味（2026-10-28）。
- ユーザーが「確か〇〇でしたよね？含まれていましたか？」と聞くときは、資料（`docs/story.md` や章のファイル）を確かめてから、あったか・なかったかを答える。

- 「Codexへの指示書は？」（2026-10-29）: Codex に回すときは、作業票（Issue）・ブランチ・下書きの PR と、Codex に貼る文を必ずそろえて渡す。Claude が自分でした作業なら、指示書がないことと理由を言う。
- 「〇〇も第N節と同じにそろえて」（2026-10-30、第4節の第8 試験強襲）: 直前の話題（補正）をそろえる。話題にしていない値（W.A.S. の数など）はそろえず、そろえなかったものを報告で並べて、そろえるか聞く。
- 新しい流れを文で指示されたとき（2026-10-30「警戒の隊をアルバレスにやられさせて…」）: どの出来事の前か、どの隊か、敵の動き、目標の数を選択式で聞いてから作業票にする。台詞は Claude が仮の案を書いて見せる。
- 「正直長さは目標であり、短くても内容が充実していたらあまり気にしなくて大丈夫です」（2026-10-30）: 長さの目安（`docs/spec.md`）に届かないことを理由に止めたり、長さだけを合わせる作業を作ったりしない。報告では長さより、何が起きたか（動き・出来事）を先に書く。
- 「これは相談ですが」（2026-10-30）: 作らずに答える（できること・違い・おすすめ）。進めるかは次の指示で。

## 働き方の改善の頼み

- 「これからは〇〇してください」「〇〇も任せてみて」のような、Claude の働き方への改善の頼み（2026-10-30「こういった私からの改善点はリポジトリ上のに書き加えてください」）: Claude の手元のメモだけでなく、リポジトリの資料に書く。分担なら `docs/collaboration.md`、指示の読み方ならこのファイル、手順なら `CLAUDE.md` やスキル。書いた場所を報告で一言伝える。
- 「簡単なテストなども任せてみてください」（2026-10-30）: 小さな直しやテストの直しも Codex に任せる（`docs/collaboration.md`「分担」）。
- 「緩めます」（2026-10-30、Codex のサンドボックス）: `codex exec` は `-s danger-full-access` で呼び、早送りとテストも Codex が回す（`docs/collaboration.md`「Codex を手元から呼ぶ」）。

## 会話と名前

- **「〜って言ってください」** と台詞が書かれていたら、その文をそのまま使う（言う人物が曖昧なら聞く）。
- **「例文」「こんな感じ」** と書かれた台詞は調子の見本で、そのままは使わない。
- 人名の読みの指定（例: 「アイゼンハウワーのドイツ語読みで」）は、その読みに合わせたカタカナにする。
- 物語の中の具体的な数（例:「人口の1/4が死ぬ」）は規模のイメージ。ぴったり合わせず、物理から自然に出る幅で案を出し、作中で数字を出すかも案にする（2026-10-11）。
- 人物の設定（出自、学歴、性格）は短い箇条で来る。足りないところは Claude が補い、補った部分を報告する。

## PR と試遊ページ

- 「マージの前に試遊ページをのせれないですか？」（2026-10-30）: いつもの試遊ページは `main` のまま、PR の版を新しい試しのページに載せる（マージしたら消してよいか聞く）。手順は `/ship`。
- 「マージ」は「`main` に取り込む」と言い添える（2026-10-30、「アーティファクトを分けたのを統合するかどうか？」と読み違えられた）。
- 「okこれでいきましょう。マージして本ページを更新し」は、PR のマージといつもの試遊ページの更新（`/ship` の4まで）。

## 見た目と承認

- 見た目の変更は、見本を見せてから入れる（`docs/spec.md`「デザインの方向性」）。「〇〇のデザインも見せてください」と言われたら、関係する部分も見本に入れる。
- 承認の言葉: 「ええ感じです」「このままで」「いいですね」「それでお願いします」。ここまで来たら実装・マージへ進む。
- 「〇〇でもいいですよ」は、Claude の案を受け入れたうえでの、別の案の許可。どちらにするか曖昧なら聞く。
- 「このままでもいいし、もっと〇〇でもいい」（2026-10-12、フェブルアーリアの見本）は承認。〇〇は少し強めて入れてよい。

## セッションの区切り

- 「整理して」（2026-10-30 から）: `/tidy-docs` を最後まで。資料の整理に加えて、Claude の行動・Codex への指示・指示の読み取り・サブエージェントの見直し（`/tidy-docs` の5）もまとめて行う。

- 「次のセッションでは〇〇からです」は、`/tidy-docs` で整理し、`docs/roadmap.md` の「次にやること」の先頭に〇〇を書く合図（2026-10-14）。
- 「一旦現作業をやめ、ロードマップを整理すること、注意点をメモに残して」（2026-10-29）: 走っているサブエージェントを止め、残った変更を「作業中」のコミットで退避し、`docs/roadmap.md` を短くして（経緯とユーザーの判断は `docs/history.md` へ）、「注意点」の節に次のセッションで気をつけることを書く。
- 「作業を始めるのではなく、まとめて」は、実装に手を付けず、決定を資料に書き、古い記述・重複を消し、これからやることを整理する合図（`/tidy-docs`。2026-10-14）。
- 「まとめて」「次に行くために」「整理してください、次に行きます」「次のセッションに行けるように整理してください」は、`/tidy-docs` で資料を整理し、やったことと次の候補を短く報告する合図。
