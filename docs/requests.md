ユーザーの指示を正しく読み取るためのメモ。指示を受けて作業を始める前に読む。これまでのやりとり（〜2026-10-04）でわかったことをまとめた。読み違えた、聞き返された、新しい言い回しが出たときは、その都度書き換えて育てる（足すだけでなく、合わなくなった記述は直す・消す）。`/tidy-docs` のときにも見直す。

## 言葉の言い換え

ユーザーは短く書き、言い換えや打ち間違いもある。下のように読む。迷ったら、近い既存の機能に当てはめて質問の選択肢に出す。
- 打ち間違い（2026-11-01）: 「紅月する」は「攻撃する」、「動きが日本で」は「動きがほしいです」。読んだ意味を一言書いてから進めた。
- 「衛星から110-120」（第6節、2026-11-01）: デナリの表面から（中心からだと岩の中になる）。読み方を一言書いて進めた。
- 「ページの更新を」「テストの前に試しのページを更新して、私にやらせて」（2026-11-01）: マージせず試しのページ（別 URL）に載せる。Codex は実装と構文の確認だけで止め、早送りと `npm test` は遊んだあと。「テストは中止でいいよ」は走っている Codex を止め、実装だけで呼び直す。
- 「整理して」に「記録には〇〇で」が付いたら（2026-11-01「第一章のステージは完成で」）、その言葉どおりにロードマップの現在地と `docs/history.md` に書く。
- 「最後の総攻撃」（第6節、2026-10-31）: 核の戦艦が2隻以下になって切り替えたあと、陽動が推進器へ取り付く段。「味方がどっか行く」は、そのとき陽動が30分で戦場を去っていたこと。

- 「〇〇は実寸でなくてもok」（2026-11-06、戦闘画面の艦種マーク）: 正しさより見分けやすさを優先してよい許可。比べる見本を出し、「0.9 0.85のいずれか」「1.1 1.2」のように幅で言われたら、両方の見本を並べて選んでもらった。
- 「〇〇は〇〇で、あとから△△に移動させて」（2026-11-05「チュートリアルは出撃画面でストーリーの一番最初にのせて、あとから演習として下に移動させて」）: 「あとから」がいつか（クリアしたら）と、前の入口（タイトルのボタン）を残すかを選択式で聞いた。
- 「これなしでほかに進めないように」（2026-11-05、チュートリアル）: 終えるまでほかの作戦をすべて鍵にする。続けて言われたデバッグの飛ばし方（「デバッグの一節をクリアを最初の状態で押すと、チュートリアルをスキップ」）も同じ PR に入れ、前からの保存（作戦を1つでもクリア済み）は済みにした。
- 「〇〇は効いてますか？」（2026-11-05「W.A.S. の遅延効果は核戦艦に効いてますか」）: コードで効く作りかを確かめたうえで、早送りで実際の効き方（遅れた時間の割合など）を測って数字で答える。作りの上で効いても、実際にはほとんど当たっていないことがある。

- **書かれたことだけをやる。** 「他は大丈夫なので〇〇だけ」「〇〇の画面だけ」のように範囲を絞ることが多い。言われていない画面や機能まで広げない。広げたほうがよさそうなときは、範囲を選択肢にして聞く（例: 「縮小」は技術ツリーの画面だけか全体か）。
- **1つのメッセージに複数の頼みが入る。** 「また」「あと」でつながる。全部拾い、話題ごとに PR を分ける。
- **「〇〇も残して」「〇〇は残してください」** は、変える対象から外すもの。忘れずに守る（例: ウィンドウの形を変えても、艦隊の上の国旗アイコンは残す）。
- **「もし今もそうなら実装しなくても良い」** と言われたら、まずコードで今の動きを確かめ、そうなっているなら作らずに報告する。
- **「これからも同じなので仕様に残して」** は、その作戦だけでなく今後すべての決まり。`docs/spec.md` に「これからの作戦もすべて」と書く。
- **「今はとりあえず〇〇して」** は、あとで正式な形（チュートリアルなど）に置き換える前提の仮の実装。資料に「仮」と、置き換え先を書く。
- **「難易度は今と同じぐらい」** は、編成を変えても勝ち負けの時刻や残りの耐久が前と近くなるよう、早送りで確かめて合わせる。

## 質問のしかた

- 曖昧なら、実装の前に選択式で聞く（ユーザーは「あいまいであれば質問してください」と念を押している）。
- **すでにあるものを聞かない。** 「下二つはもうありますよね？」と返されたことがある。聞く前にコードと資料で今の状態を確かめ、ないものだけを聞く。
- **仕様上ありえない場合を聞かない。** 「てか仕様上そうならないのでは？」と返されたことがある。選択肢を作る前に `docs/spec.md` と照らし合わせる。
- 選択肢に合わないとき、ユーザーは自由記述で答える。自由記述の答えは選択肢より優先し、そのまま仕様として扱う。
- 自由記述の欄に、その質問ではなく別の話題の答え（前の案の取り消しなど）を書くことがある（2026-10-09）。書かれた内容は仕様として扱い、答えのなかった質問は「決めてほしいこと」に残す。
- 番号付きで質問すると、ユーザーは「1 〜 2 問題ない」のように番号で答える。「問題ない」はそのまま採用の意味。
- 「〇〇は適当に」は Claude が決めてよいという意味。決めた内容は資料に書き、報告で一言伝える。
- 置き場所を選ばせるときは、物語の中の施設（宇宙港など）を選択肢に入れる。2026-10-31 に W.A.S. の出どころを聞いたら、選択肢（推進器のそばの格納庫など）でなく自由記述で「宇宙港」と答えた。
- 数の単位は、ほかの作戦と同じものを使い、聞かない（2026-10-31「編隊数？は他のと同じ単位でお願いします」。W.A.S. は「機」）。
- 「NでテストするようにN1・N2・N3」: それぞれを早送りして表にし、どれにするかはユーザーが選ぶ（2026-10-31、W.A.S. 40・80・120 → 40）。極端な結果は、0 の場合と比べて原因を切り分けてから見せる。
- 「〜で動いているのでは？」（仕組みの推測、2026-10-31）: まずコードを読んで当たっているかを答え、原因と直し方の案を選択式で出す。作るのは選ばれてから。
- 地形や配置は、世界設定（地球の軌道上か、月より遠いか、など）に照らして自然かを確かめてから出す。「あからさまな隕石帯」「こんなまっすぐですぐ横にあるわけない」と指摘されたことがある（2026-10-09）。決まった艦種でも、物語の時点で開発されていないものは出さない（強襲母艦）。
- 「この二つをうまいこと組み合わせたい」は、選択肢のどれかではなく、前の案と新しい指示を両方生かす案を Claude が考えて書くという意味（2026-10-09、第4節の盾と負けイベント）。案は「決めてほしいこと」に回して確かめる。
- 「わたしの前提について討論しましょう」と番号つきの前提が来たら、作らずに議論する。前提ごとに賛否と理由、今の作りとのずれ（事実）、詰めるべき点を出し、分かれ道を番号つきの選択肢（推しを先頭）で聞く。答えは「1①」「2①と②の両方で〜」の形で来る。「両方」は両方の案を組み合わせる意味（2026-10-20、両陣営の技術と強さ）。
- 「計画はこんなのがイメージです」と両軍の動きの構想が来たら、すぐ作らずに、構想を資料に書き、曖昧な点（向き、何を数えるか、合図）を選択式で聞き、`wos-strategy` に布陣・数・流れの案を出させて見せる（2026-10-28、第6節の陽動）。「左上・右下」は正面から見た向きで、高度も含む（左上＝西の上、右下＝東の下）。
- 「できるだけ基礎の変数は変えないでください」（2026-10-29、第6節の釣り合わせ）: 全作戦で共通の値（艦種の性能、W.A.S. の1隻8機、耐久・打撃の倍率、`data/ships.js` の数）は変えず、その節のデータ（隊の数と内訳、置き場所、出る時刻、動き、その節だけの物の耐久）で合わせる。共通の値を変えるしかないときは、先に聞く。
- 「耐久を調節するとかは許されません」（2026-10-30、ユーザーが Codex に。第4節の作業票 #241）: 釣り合わせで艦の耐久（本軍・敵・その節の隊の `hp` や倍率、傷み `hurt`、回復）を変えない。数・内訳・出る時刻・動き・速さで合わせる。作業票の「届かないとき」にも耐久は入れない。
- 選択式の答えが自由記述で、どの選択肢とも違う短い言い方（例:「陽動はほしいです、一部を戻して」）なら、読める意味を2〜3通りの選択肢にしてもう一度聞く（2026-10-29。答えは「陽動から割いて戻す」だった）。
- 「〇〇のサブエージェントの最適化も」は、`.claude/agents/*.md` に、ユーザーの好む作戦や動き（陽動、引きずり出し、段階の切り替えなど）が出やすくなる指針を足すという意味（2026-10-28）。
- ユーザーが「確か〇〇でしたよね？含まれていましたか？」と聞くときは、資料（`docs/story.md` や章のファイル）を確かめてから、あったか・なかったかを答える。

- 「Codexへの指示書は？」（2026-10-29）: Codex に回すときは、作業票（Issue）・ブランチ・下書きの PR と、Codex に貼る文を必ずそろえて渡す。Claude が自分でした作業なら、指示書がないことと理由を言う。
- 「〇〇も第N節と同じにそろえて」（2026-10-30、第4節の第8 試験強襲）: 直前の話題（補正）をそろえる。話題にしていない値（W.A.S. の数など）はそろえず、そろえなかったものを報告で並べて、そろえるか聞く。
- 新しい流れを文で指示されたとき（2026-10-30「警戒の隊をアルバレスにやられさせて…」）: どの出来事の前か、どの隊か、敵の動き、目標の数を選択式で聞いてから作業票にする。台詞は Claude が仮の案を書いて見せる。
- 「正直長さは目標であり、短くても内容が充実していたらあまり気にしなくて大丈夫です」（2026-10-30）: 長さの目安（`docs/spec.md`）に届かないことを理由に止めたり、長さだけを合わせる作業を作ったりしない。報告では長さより、何が起きたか（動き・出来事）を先に書く。
- 「これは相談ですが」（2026-10-30）: 作らずに答える（できること・違い・おすすめ）。進めるかは次の指示で。

## 会話と名前

- **「〜って言ってください」** と台詞が書かれていたら、その文をそのまま使う（言う人物が曖昧なら聞く）。
- **「例文」「こんな感じ」** と書かれた台詞は調子の見本で、そのままは使わない。
- 人名の読みの指定（例: 「アイゼンハウワーのドイツ語読みで」）は、その読みに合わせたカタカナにする。
- 物語の中の具体的な数（例:「人口の1/4が死ぬ」）は規模のイメージ。ぴったり合わせず、物理から自然に出る幅で案を出し、作中で数字を出すかも案にする（2026-10-11）。
- 人物の設定（出自、学歴、性格）は短い箇条で来る。足りないところは Claude が補い、補った部分を報告する。

- 「〜にするのは？」「〜は？」「名前のセンスはどう？」（2026-11-07、編成ボーナスの名前）: 作らずに評価を返す。よい点、気になる点（ゲームの中の言葉とぶつかる、条件と意味が合わない、長さ）と、代わりの候補を2〜3個。決まってから入れる。「〜軍」は戦区軍と、「作戦」は節と紛らわしい、のようにゲームの用語との重なりを必ず見る。
- 「命名法や私の好みも記録しておいて」（2026-11-07）: 決まった名前だけでなく、名付けの決まり（形、避ける言葉、長さ）と、選ぶときの好みを `docs/spec.md` に書く。
- 「それに合う史実の言葉は？」: 実在の言葉を、意味のまとまりごとに出典つきで並べ、条件に合うものを勧める。

## PR と試遊ページ
- 「マージまでしといて」（2026-11-07）: 待っていた確認（台詞が OK か）への承認。テストと CI を通してマージし、試遊ページを載せ直す。
- 消してよいかの問いに「問題ありません」（2026-11-07）は、消してよいの意味。
- 対照表や試しのページへのコメントの「ここは〇〇では？」は、直してほしい合図のことがある（2026-11-06「ここは作戦後では？」→ 後で「はい」で移した）。理由を答えたうえで、移すかを聞く。

- 「マージの前に試遊ページをのせれないですか？」（2026-10-30）: いつもの試遊ページは `main` のまま、PR の版を新しい試しのページに載せる（マージしたら消してよいか聞く）。手順は `/ship`。
- 「マージ」は「`main` に取り込む」と言い添える（2026-10-30、「アーティファクトを分けたのを統合するかどうか？」と読み違えられた）。
- 「okこれでいきましょう。マージして本ページを更新し」は、PR のマージといつもの試遊ページの更新（`/ship` の4まで）。
- 「試遊ページを更新して」（2026-11-05、変更を入れた直後）: PR → CI → マージ → いつもの試遊ページ（`/ship` の4まで）。
- 「先に乗せて」（2026-11-05、テストとマージの前）: 作業中の版（コミット前でも）を、いつもの試遊ページへ先に載せる。テスト・PR・マージはそのあと続け、マージ後に `main` と同じ中身か確かめる（同じなら載せ直さない）。
- 「マージして」「マージします」「進めて」（2026-10-31）: オートモードの安全チェックでコミット・push・マージが止まったときの承認。CLAUDE.md と `/ship` ではマージは Claude の判断でよいが、Claude Code の安全チェックはそれとは別に止める。

## 見た目と承認

- 「元のマークなどはそのままでタブ自体を変えて」（2026-11-05、戦闘画面の窓の見本）: 中身（印、ゲージ、ボタン）は残し、外側の枠と見出しだけを変える。作り直した中身の案は要らない。
- 「何パターンか」「完全に作り直し何パターンか」（2026-11-05）: 2〜3案の見本の画像。実際の画面に HTML と CSS を重ねて撮り、比べ用に並べた1枚も添えた。
- 「〇〇はまだです」（2026-11-05「右上はまだです」）: 入れた形に不満がある。何が足りないか曖昧なら選択式で聞く（このときは「見た目がまだ合っていない」→ 続けて並びの指定と作り直しの案を求められた）。
- 見本の画像に赤い丸で囲み「ここに〇〇を」（2026-11-05）: その場所に置く指示。丸の大きさは目安で、形は案を出して選んでもらう。
- 画面の部品の呼び名（2026-11-05）: 「マウスオーバータブ」はマウスを載せると出る札（名前と艦種ごとの残り）。「艦隊のマークと数字の艦の簡易的なタブ？ボタン」は地図の上の印（艦種マーク＋隻数）。Claude は後者を札と読み違えて札を不透明にし、ユーザーが画像で指し直した。候補が2つあるときは、どちらかを撮った画像で聞くか、両方の候補を挙げて確かめる。

- 見た目の変更は、見本を見せてから入れる（`docs/spec.md`「デザインの方向性」）。
- ユーザーは iPhone で遊び、スクリーンショットを送ることがある（2026-11-06）。画面の直しは、スマホの大きさ（390×780、3倍）でも撮って確かめる。赤丸と短い一言（「第を前につけてください」）は、その場所への指示。収めるために一緒に変えたこと（一覧の幅）は報告で言う。
- 「今のを一旦保存して何パターンかみせて」（2026-11-06、技術ツリーの線）: 今の形をブランチに残したまま、案を画像で並べる。選ばれた案（「Cで」）を入れる。
- 「私が言ってるのは今とりあえずどんな感じか見たいだけなのでみせて」（2026-11-06、研究の費用）: 作ることでなく、今の値を表と画像で見せる。
- 「イメージですよ」（2026-11-06、艦種の役割の例）: 挙げた例はそのままでなくてよい。離れるときは理由を書く。
- 「全体的に少し高くしたい」（2026-11-06）: 倍率を選択式で聞いた（1.2倍）。「〇〇のデザインも見せてください」と言われたら、関係する部分も見本に入れる。
- 承認の言葉: 「ええ感じです」「このままで」「いいですね」「それでお願いします」。ここまで来たら実装・マージへ進む。
- 「〇〇でもいいですよ」は、Claude の案を受け入れたうえでの、別の案の許可。どちらにするか曖昧なら聞く。
- 「このままでもいいし、もっと〇〇でもいい」（2026-10-12、フェブルアーリアの見本）は承認。〇〇は少し強めて入れてよい。

- 「〇〇をもっと広々と使って。△△以外を大体使って構いません」（2026-11-05、技術ツリー）: 空いた場所をなくし、説明の欄を押した物のそばのウィンドウにする形を、ほかの画面でも基本の考え方として `docs/spec.md` に書いた（「空間の理想的な使い方」とユーザーが呼んだ）。「よこはいいです いったん」は、今回は触らない（後で頼まれるかもしれない）。

- 「こんな感じで」と見本に赤で描いた絵（2026-11-05、軍港の構図）は、次に撮る形の指示で、承認ではない。Claude がそれでコミットと push をして「誰も許可してませんよ？」と言われた。見本の承認（「いいですね。それで行きましょう」）のあとも、コミット・push・マージは許可をもらってから。「このままで、終わったら整理して」は、そのまま出して（コミット・push）から `/tidy-docs`。
- 見本の写真に円と線を描いて「円に地球、棒が港」（2026-11-05）: 円は地球を置く場所、線は港の柱の向き。カメラの位置は、柱の両端と地球が描いた場所に写るよう数で解いて撮った。「もっと引きで」「根本から」「港が長く見える角度」「表面が少し見える」は、カメラだけを変える指示（形は変えない）。試しの写真はスクラッチパッドの写しで撮り、作業フォルダは決まってから直す。
- 「背景用」（2026-11-05「あれですよ背景用のやつですからね」）: 板の後ろに出す絵なので、細かさより構図と雰囲気。写真も板と文字を消した「背景だけ」を撮って見せる。

- 3Dモデルの見本（2026-11-12〜13）: 見本ページの絵に赤丸を付けた写真で直す場所を指す。赤丸の読みは資料に「Claude の読み」と書き、写真は会話の記録から取り出して確かめる（リポジトリには入れない）。参考の画像は版権があるので見るだけで、形は写さず混ぜて独自にする。「これらでokです」のあとにも直しが続くことがある。ゲームに入れるのは「これで大丈夫です」など最後の版への承認を待ってから。
- 「つながってない箇所がある」（2026-11-13）: 部品が体から浮いている。目で見るだけでは見落とすので `tools/model-floaters.cjs` で全モデルを確かめる。
- 「上の表はこの時代の相対的な力で、貫通力は絶対的な力」（2026-11-13、W.A.S. の武装）: 相手にできるものの表は残し、絶対値（貫通力・装甲）は未来の値として高めに置いて、表と食い違わないようにそろえる。
- 「必要に応じてテストや実装は codex に任せて上限を開けて」（2026-11-13）: 長いテストの回し直しや機械的な直しは Codex に回し、Claude の使う量を抑える。
