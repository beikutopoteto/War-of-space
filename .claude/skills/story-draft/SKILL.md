# 物語の叩き台（/story-draft）

毎回同じ型で書けば、読む量も迷いも減る。この順で進める。

## 1. 置き場所（ここだけ覚える）

| 中身 | 置く場所 |
|---|---|
| 章の流れ、人物、各節の狙い・人物・あらすじ・戦闘の流れ・会話の案・その節で決めてほしいこと | `docs/chapterN.md`（章ごとの物語の正本） |
| 作戦の表（全章）、章で新しく要る仕組みの一覧、各節の編成・数値・仕組みの決まり・作るもの・実装の記録 | `docs/campaign.md` の「第N章 各節の実装メモ」 |
| 章をまたぐ世界設定（年表、技術、地名、勢力） | `docs/story.md` |
| ゲームに出す会話と通信の文（決まったもの） | `data/operations.js`（実装のとき） |

物語と仕組みが混ざる「戦闘の流れ」の表（段階・時刻・起きること・案内）は物語側（`chapterN.md`）に置く。隻数や数値は `campaign.md` に置く。

## 2. 読む（必要なところだけ）

- `grep -n "^#" docs/chapterN.md docs/campaign.md` で見出しを見てから、次の部分だけ読む。
  - `chapterN.md`: 1（章の骨組み）、2（人物）、3 の対象の節と前後の節、4（伏線）、最後の「ユーザーに決めてほしいこと」。
  - `campaign.md`: 章の作戦の表、「新しく要る仕組み」、前の節の実装メモ。
- `docs/story.md` は地名・技術名を grep して、出てくる行だけ読む。
- 仕組みの案を出すときだけ `docs/menu.md` の関係する節（索敵、艦載機と W.A.S. など）を読む。
- 前の節の実際の会話や艦隊は `grep -n "<作戦のid>" -A60 data/operations.js` で見る。

## 3. 書く（型）

`chapterN.md` の「3. 各節の流れ」の該当節にある短い要約を、次の型の詳しい版で置き換える。

```
### 第M節「作戦名」
作成: 日付。名前・時刻・数値はすべて仮。編成と仕組みは `docs/campaign.md` の「第M節」。
#### この節の狙い        … 前の節との手触りの違い、教える操作
#### 登場人物            … 表（人物｜立場｜この節での役割）。新しい人物は「新・仮」と書き、2 の人物表にも足す
#### あらすじ            … 前 → 戦闘の状況 → 後、次への引き
#### 戦闘の流れ          … 表（段階｜時刻（作戦の時計、戦闘1秒＝5分）｜起きること｜案内すること）、勝利・敗北、マップの略図
#### 会話の案            … 前／戦闘中の通信ログ／後（勝利・敗北）
#### ユーザーに決めてほしいこと … 番号つき。各項目に Claude の案を添える
```

`campaign.md` の「第N章 各節の実装メモ」に `### 第M節「作戦名」（案）` を足し、自軍・敵・舞台（仮）、仕組みの決まり（`#### …（案、数値は仮）`）、`#### 作るもの` を書く。新しい章なら `docs/chapterN.md` を `chapter1.md` と同じ章立てで作り、CLAUDE.md の「資料」の表に1行足す。

## 4. 守ること

- ユーザー決定（「ユーザー決定 日付」の記述と `docs/spec.md`）は変えない。変えたい案は「決めてほしいこと」に回す。
- Claude が置いた名前・数値・時刻は「仮」と書く。版権の名前、「M.A.S.」は使わない。
- 章の伏線（`chapterN.md` の 4）と人物の役割に合わせる。地名や技術は `story.md` と食い違わせない。
- 乗員の出身はばらばらにする（地球連合は各国の人の集まり）。

## 5. 仕上げ

- `docs/roadmap.md` の「現在地」の「次」を、叩き台への返事待ちに直す。
- `/ship` の手順で PR にしてマージする（資料だけなので試遊ページは載せ直さない）。
- ユーザーには、叩き台の要約（狙い、あらすじ、戦闘の流れ、新しい仕組み）と「決めてほしいこと」を見せる。
