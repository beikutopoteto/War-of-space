# 地上戦の道探しと重さ（2026-11-19、#461）

経路の一致を確認できた川の表を残した。指揮官の移動を分ける試行と再編先のキャッシュは、組み合わせた早送りで戦況が大きく変わったため取り下げた。作戦規模を決めるには、採用した変更だけの実戦計測が必要。

## 実戦の計測

試行の128小隊では、仮の目安のうち初回1,000 ms以内に収まった。1フレーム33 ms以内と途中最長200 ms以内は未達。広い視点の中央値は64・128小隊の試行で各2フレーム分なので、規模を比較するにはサンプルが少ない。

128小隊/軍の CPU サンプリングでは、修正前の計算時間に対する包括時間は `groundPath` 70.4%、`groundRiverAt` 23.4%、再編先の検索 5.2%。試行ではそれぞれ66.3%、13.9%、4.6%で、経路の発令待ちを処理する関数が50.1%を占めた。試行の自己時間の上位は `groundPath` 27.0%、`groundRiverAt` 13.9%、道路帯の `contains` 9.0%、`groundElevation` 7.0%。包括時間は呼び出した関数の分を含む。

体の動き `groundBodyTrack` は前4.0%、試行4.6%。試行の128小隊/軍で強化歩兵・重強化歩兵を仮に1小隊12体にした30ゲーム秒は、全1,712体、計算中央値30.1 ms、体の動き6.9%。いずれも1割未満なので、体どうしのよけ方には手を入れなかった。

## 川の表と経路の照合

セル中心の渡河判定を表に保存した。川が届く可能性のあるセル内では、中心以外の点を従来どおり実座標で検査する。橋の版が変わると、次の経路探索で表を作り直す。Chromium での生成は検証場26.6〜38.5 ms、バイコヌール5.4 msだった。

旧版と現版を独立した Node VM で実行した。地図ごとに固定乱数で選んだ50組（うち25組は川の周辺）を車両と歩兵で探索し、到達可否、経路の全座標、コスト、長さが一致した。両版とも到達不能の組も一致に数えた。時間は各50件の合計で、表の生成を含む。

| 地図 | 兵科 | 一致 | うち経路あり | 探索時間 修正前 → 川の表 |
|---|---|---:|---:|---:|
| バイコヌール | 車両 | 50/50 | 28 | 7.14 → 7.60 秒 |
| バイコヌール | 歩兵 | 50/50 | 50 | 9.70 → 9.84 秒 |
| 300 km 検証場 | 車両 | 50/50 | 50 | 38.81 → 30.00 秒 |
| 300 km 検証場 | 歩兵 | 50/50 | 50 | 37.61 → 29.80 秒 |

既存の19ケースも一致し、仮設橋の完成、破壊、リセットと同じ状態での表の再利用を確認した。再現は `node tests/ground-path-perf.cjs --baseline=旧版のterrain.js`。

## テスト

- `npm run check-docs`、構文確認、`git diff --check` は成功。
- 採用した版で1回目の `npm test` は、第6節の戦艦経路・鉱山マーカーの表示確認1件が失敗。ページ例外は0件。この確認だけを同じ手順で実行すると、main と採用した版の両方で成功し、地上の経路探索の呼び出しは両方とも0回だった。全体実行で表示が欠けた原因は未確定。
- 2回目の `npm test` では第6節の表示確認が成功した。別の視点スティックの確認1件が失敗し、500 ms で17°（成功条件は20°超）だった。ページ例外は0件。単独実行では main と採用版でともに23°回って成功し、地上の経路探索は0回。視点の回転は描画1フレームあたり最大50 msぶんのため、500 msのあいだの描画回数に左右される。全確認の同時成功は得られていない。
