# 天体とマップの作り方

第4節「デナリの盾」（2026-10-09〜10）で、資源衛星・岩くずの雲・民間区画・地表の砲台・段階のある作戦を作った。そのときに覚えたことを、次のマップ（第5節以降の衛星、ステーション、雲など）を作るときのためにまとめる。決まった仕様は `docs/spec.md`、第4節の数値と経緯は `docs/campaign.md`。

## 1. 座標と大きさの目安

- 戦場は x が東（+）、z が南（+）。北（火星側）は z がマイナス。高度は y（作戦データでは `alt`）。作戦データの位置は `[x, z]` と `alt` で書く。
- ユーザーが基地の向きを言うとき（ユーザー決定 2026-10-16。第5節の総基地で。言い方の説明で、コードの座標は変えない）: 基地を上から見て、基地の長い向きを横切る直線が x、基地の長い向きが y、真上が z+。y と z は x の中点（基地の真ん中）を通る。コードに直すと、ユーザーの y は東西（コードの x）、ユーザーの z は高さ（コードの y、`alt`）、ユーザーの x は南北（コードの z）。「y+− と z+ の三方面」は、基地の東西の両端と真上（2026-10-16。最初は「x+− と y+」と言い、あとで直された）
- 第4節の大きさ: 衛星の半径30（ユーザー決定: 大きめ）、居住区の民間区画は半径18、展開は南の [0,110]、離脱点は [-127,127]（2026-10-12 に [-100,100] から）、岩くずの雲は中心から東の端で110、北西の端で92。
- 行動範囲: 移動の指示でクリックできるのは、作戦フィールドの中心から200以内（`battle/hud.js` の `groundAt`）。離脱点など、プレイヤーが艦を連れていく目標は、輪の外側まで200以内に置く（2026-10-15。第4節の離脱点が約212にあり、行けなかった）。
- 視点は作戦の `view:{target, dist, dir}`。`dist` 230 で全体が入る。
- 場所の名前（`sectors`）は平面に出る小さな名札。天体、居住区、港は `state.js` の `reset()` が自動で足す。

## 2. 天体（`op.body`）

### データ
```
body:{name, sub, r, lobe:{c:[x,y,z], r}, craterA, mine:{dir, a, depth, steps}, groove:{w, depth},
      blocks:[{name, sub, pos:[x,z], alt}], port:{name, sub, pos:[x,z], alt, r}}
```
- `blocks` は居住区。町はその方向のクレーターの底に建つ。`port` は宇宙港の輪（戦闘母艦の着陸点）。
- `lobe` はこぶ。半径 `r` の球を足す（ユーザーの画像2枚目の形）。`mine` は段々の露天掘り。`groove` は町どうしと鉱山を結ぶ溝（鉄道）。

### 形の作り方（`battle/scene.js` の `makeBodyShape`）
- 形は「中心からの向き d → 半径 R(d)」の式で表す。表面の高さはどこでも式で分かる（`bodyShape.R`、`bodySurface`）。艦を表面の外へ押し出す処理（`keepOffBody`）は、毎フレーム光線を飛ばさずに済む。
- 光線（`bodyHit`）を使うのは、砲台を岩の面に置くときだけ。置く1回だけなので重くない。
- R(d) の中身は上から順に:
  1. 押しつぶした楕円体（`sq`）に、なめらかな sin の凹凸をかける。
  2. こぶとの和（大きいほうの半径を取る）。
  3. 割れた平らな面（ランダムな向きの平面70枚で少しずつ削る）。ゴツゴツして見えるのはこれが一番効く。
  4. 細かいとがった凹凸。
  5. 小さなクレーターと岩の盛り上がり48個。町と鉱山の上には置かない。
  6. 町のクレーターと、段々の鉱山。
  7. 溝（大円に沿って削る）。クレーターの中は削らない。
- メッシュは `IcosahedronGeometry(1,56)` の頂点を R(d) まで動かす。`flatShading` の岩の色。

### 町・チューブ・港（`buildBody`）
- 町はクレーターの底に、小さな住居モジュールを 5×4 のゆるい格子で並べる。
- 低いところは丸いチューブ、上は橋だけでつなぐ（ユーザー決定）。窓の灯りを粒で足す。
- 溝がクレーターから出るところに、トンネルの口を置く。
- 町と町の間には細いチューブを2本、溝の横に通す。
  - 表面から0.45浮かせる。小さな穴の上は、前後2点の高いほうに合わせて水平に渡す。
  - 支柱で支える（ユーザー決定）。
- 鉱山には作業灯と機械、港には腕・台座・輪を置く。

### 気をつけること（失敗したこと）
- **Three.js r128 の `IcosahedronGeometry` の detail は分割数**。細かい溝やクレーターを出すには 50 以上が要る（2〜4 では角ばる）。
- **ハッシュの乱数を丸めた凹凸は段々（ブロック状）に見える**。sin の重ね合わせか、平面で削るほうがよい。
- **細かすぎる凹凸**（周波数30くらい）は、メッシュの細かさと干渉して縞になる。
- 溝をクレーターの中まで掘ると、町が穴に埋まる。
- 名前のぶつかり: `battle/*.js` は外側の名前を共有する。`scene` のような短い名前は `scene.js` のシーンとぶつかって、全部が止まる（`playScene` に改名した）。

## 3. 岩くずの雲（`op.debris`、`op.debrisTilt`）

- 球を重ねて塊にする（`[{pos:[x,z], alt, r}]`）。第4節では作戦データの中で関数で作っている。中心からの角度と距離を少しずつ変え、太さを始まりから先へ細くする。
- `debrisTilt` は東西の軸のまわりの傾き（度）。見た目の傾きで、各球の `alt` も同じ傾きで計算する。
- 見通し: 見る艦と見られる艦を結ぶ線が雲の球を通ると、見えない（`sim.js` の `debrisBlocks`）。20以内（`DEBRIS_NEAR`）なら見える。中の艦は速度0.75倍。雲に隠れた敵は、出るまで見えない（奇襲に使う）。
- 岩は `rock()` で作った、いびつな形4種類。色の薄い霞（`dustMat`）を重ねる。

**置き方でユーザーに言われたこと**
- まっすぐな「隕石帯」はだめ。地球の軌道上の衛星のそばに、まっすぐな帯がすぐ横にあるのは不自然。
- 採掘で出た砂利や鉱滓が、衛星を中心に弧を描いて巻く形にした（ユーザーが図に赤い線を描いた）。
- 距離は「離れすぎ」「もっと近く」を3回やりとりして、185 → 170 → 140 → 110 になった（今は東の端110から北西の端92へ近づく弧）。最初は近めに置くほうがよい。
- 傾きは30〜40度。平面の下に出てもよい。

## 4. 民間区画（`op.civil`）

- 居住区のまわり半径 `r` の球。
- 被害（`civHit`）が出るのは次のとき。上限 `cap` を超えると負け。
  - こちら（駐屯隊と本軍）の砲が区画の中の敵艦を撃ったとき（打撃1につき `perDmg` 人、艦載機は `perCraft` 人）。
  - 区画の中で敵艦が沈んだとき（`perSink` 人）。
  - 敵の `ai:'raid'` が居住区を撃ったとき（`perRaid` 人）。
- **地表の砲台（`fixed`）は撃っても被害なし**（岩の上。ユーザー決定 2026-10-10）。
- 本軍（友軍）は区画の中の艦を撃たない（`fireTargetOf` の ok、`allyAI` の foes）。砲台は撃つ。
- 自軍の艦載機は、命令がなければ区画の中の艦を狙わない（`craftTarget`）。
- 区画の縁は琥珀色のフレネルの殻と輪で見せる（`zoneMat`）。

**学んだこと**: 「味方は区画の中を撃たない」と「敵は区画の中に入れる」が重なると、敵が区画に居座り、味方は棒立ちで沈む。敵に `keepOut:true` を付けて区画の縁へ押し出すと、撃ち合いになる（`keepOutOfZones`）。守備隊がわざと区画に逃げ込むとき（`ai:'shield'`）は付けない。これは物語の「住民を盾にする」の場面。

## 5. 地表の砲台

- 作戦の敵に `type:'aa', speed:0, fixed:true` で置く。
- `reset()` で `bodyHit` を使い、岩の面に付ける。`s.base` と `s.up` に、置いた点と面の向きを持つ。
- 描画は `loop.js` の `groundGun`。付け根は面にぴったり付ける（ユーザー決定）。
- 小さめに作る（scale 1.1）。形は `shapes.js` の `SHAPES.aa`。
- 形（第4節と第6節、ユーザー決定 2026-10-23、見本 B）: 地球連合が賊よけに作った単装の小型砲台（駆逐艦の主砲のような形。資源衛星は小さいので、第5節の戦艦の主砲のような二連装ではない）。八角の砲座と回る台に、前のとがった角のステルスの家（横の面が屋根へ内に傾き、屋根に低い段）、前の細い口から細い砲身1本を少し上げて構える。大きさは前の二連装と同じ（台の幅）。向きは `f.heading`、砲身の上げ下げはない（今は一つの形のまま）。見本は「今・A 案D の家・B 角のステルス・C B＋八角の胸壁とセンサー」を拡大図とデナリの鉱山の縁（距離35と80）で並べた（スクラッチパッドのスクリプト。リポジトリには入れていない）。
- 画面の印（ユーザー決定 2026-10-23）: 第5節の味方の砲台と同じ小さな四角に点（見本 B）を、共和国の色で。名前は選んだときだけ（`state.js` の `gun` の印）。
- 対空照準を高くすると（`aa:9`）、艦載機をよく落とす役になる。

## 5.1 推進器（第6節、ユーザー決定 2026-10-23、見本 B を1.5倍）

- 共和国が付けた大型推進器（フェブルアーリアの岩を運んだのと同じ型。鉱山の岩を核融合で噴く。`docs/story.md` 5.2）。形は `shapes.js` の `SHAPES.thr`（scale 1 で描く。見本の1.5倍の大きさを形に入れてある。2倍と言ったあと1.5倍に直した）。
- 形（見本 B、付け根は B2）: 岩に盛った低い六角の土手に、上へ細る六角の炉の下半分を埋める（細い首と脚は「回りそう」に見えたのでやめた）。土手から鉱山へ供給管。鐘のない磁気ノズル（広がる八角の輪4つを細い梁3本で留める）、炉の両わきに放熱板。高さは戦艦の長さくらい。
- 軸（ユーザー決定 2026-10-23）: ノズルは形の上（+y）へまっすぐ。置くときは上を「デナリの中心から外への向き」にそろえる（岩の面の向き `s.up` ではなく）。押す力の線が中心を通らないとデナリが回ってしまうため。前の案の「みな同じ向きへ傾ける」はやめた。
- 置き方は砲台と同じ（`type:'thr', speed:0, fixed:true`。岩から .34 × scale の高さ。上だけは中心からの向き）。第6節（`denaliBreak`）に置いた（2026-10-24。並びは `docs/menu.md`「第6節の舞台」）。
- 置き場所（ユーザー決定 2026-10-24、`wos-story` の案A。方位は南から東へ、高さは上が正、デナリの中心から）: 西（方位−90度・高さ0度、岩の盾A）、西の上（方位−90度・高さ40度。守りが薄い）、東（こぶの下、岩の盾B）、北（裏、岩の盾C）に3基ずつ。西と西の上は速さを殺す噴射に使ったもので、東と北が核のあとに予想点を戻す（`docs/story.md` 5.2）。噴くとき（上）の見本は東と北だけに出す。
- 噴くとき（起爆のあとで予想点を戻すあいだ）の見本: ノズルの口から、加算の円錐を2つ（細く明るい芯と、広く薄い霞。橙〜白で、口が明るく先へ薄れる）。入れるのは推進器が噴く仕組みと一緒に。

## 5.6 総基地の砲台（第5節、案I。ユーザー決定 2026-10-17、ユーザーのイメージ図と案D から）

- データ: 砲台に `pit:true` を付けると、`pos` を岩の表面の実際の [x, z] として案I の形で置く（`battle/base.js` の `pitBuild`・`pitDraw`）。`inf` はまわりを守る強化歩兵の人数。
- 形: 岩にまっすぐ下りる丸い竪穴（底あり）。まわりに八角の砲座（C）と丸い縁（A）。中は案D の砲塔（真上から見て前が縦長の台形・長方形・後ろが短い台形、屋根の前が低く、前面の縦長の口から二連の砲身）で、全部地面の下にある。360°回る輪（向き）と、輪を横切る棒（上下角の軸）に載り、二連の砲身だけが穴から出る。D の砲塔が真上を向いても地面より下に収まるよう、竪穴は太め・深め（`PIT_R` .8、軸の深さ .8）。仰角は48〜90度（仮）で、竪穴が細いのでそれより低い相手は撃たない（`battle/sim.js` の `pitCan`）。ふだんは80度でまっすぐ近く上を向く。大きさは前の砲台の2倍。中は暗い灰色の壁と底に誘導灯。光（色と発光）はほかの艦の80%（ユーザー決定。光りすぎて見えにくかった）。
- 穴の見せ方: 口の円でステンシルに印を付け（手前に何もないところだけ）、そこへ竪穴の壁と底を岩より先に見えるように描き（深さはいつも通す）、そのあと砲塔・輪・棒・誘導灯をふつうの深さで描く。`joinParts` に渡す形は `toNonIndexed()` にしておく（しないと形が壊れて穴が見えなかった）。後処理（`EffectComposer`）の描画先にステンシルを持たせた（`battle/scene.js`）。
- 沈んだ砲台: 暗い色になり、砲身が下がり、誘導灯が消える。強化歩兵も消える。
- 見本の流れ（2026-10-17）: A 艦砲塔・B レール砲・C 八角の砲座 → 「A と C を組み合わせ、砲身をつける部分は赤線の形（縦長の台形・長方形・縦に短い台形）」→ 真上から見た形（P）と正面から見た形（E）→ 「P を90°起こし、地面の縦長の穴に埋める」（F）→ 「丸い穴の中、地表より下にあり、砲身だけ外に見える。スタビライザーで射角と向きを変える」（G）→ 「中がもう少し見えるように」→ ユーザーのイメージ図（横: 地中の竪穴に砲塔、上: 360°回る輪と上下角の棒）から案H → 「中の砲身とそれが付いているものは D でいい」で案I。

## 5.5 総基地のゲートと強化歩兵（第5節、2026-10-16）

- データ: `body.blocks` に `gate:true` を付けると、町を建てずにクレーターの底へゲートを置く（`battle/base.js`）。仕組みの数は `op.base`（`data/operations.js` の先頭の説明）。
- ゲートの形（ユーザー決定 2026-10-16。見本から選んだ）: 南北に長い八角形のふた（長さ約24 × 幅約15）。南北の両端にヒンジ、真ん中を東西に横切る分かれ目で北と南の2枚に開く（戦闘中は閉じたまま）。三角の板が中心の小さな八角に集まり、板ごとに一段高い内板、角に誘導灯、縦のシャッターの継ぎ目。上に八角形の状態の帯（青 → 琥珀 → 灰色にばつ）。
- 強化歩兵: 画面でいつも約3px の点（友軍の色に暗い縁取り）。ゲートのまわりの岩の面に組で置く。撃つときは細い光の線と、ときどき対戦車ロケットの白い細い尾。
- 見本の作り方: ゲームを開き、`page.evaluate` でメッシュと HUD を足して撮った（スクラッチパッドのスクリプト。リポジトリには入れていない）。町とパイプがゲートに重なるときは、町を除く範囲を広げた。

## 6. 段階のある作戦の部品（第4節）

### 作戦の時計
- `clockScale`: その作戦だけ時計の速さを変える（第4節は0.5）。
- `span`（2026-10-12）: 作戦の時計で何分続くかを書くと、時計の速さが規模（`scale`）の目標の秒数に合う（`clockScale` より先）。艦の速さは変わらないので、動く距離（船団の航路など）は1倍速の長さに合わせて延ばす（各作戦の値は `docs/menu.md`。第4節は630、第5節は720）。
- 時計を遅くしたら、分で書いた長さ（揚陸の `hold`、収容の速さなど）が実時間で何秒になるかも見直す。

### 戦闘母艦の流れ（`op.carrier`）
- 着陸: 港の輪で止まる → 占領（`landPhase`）。`body.port.openAt`（分）より前は輪の中でも待つ（早く降ろして前半の波を飛ばされないように）。
- 作戦変更（`evac`）: 友軍の隊が全滅、戦艦の隊（`line`）が `lost` の割合だけ沈む、または `max` 分たったとき。ただし着陸から `min` 分までは変えない。ここで収容が始まる。
- 収容: 1時間に `rate` 人、上限は `people` 人。
- 切り上げ（`cut`）: 戦艦の隊が `sunk` の割合だけ沈むか、母艦の耐久が `carrier` の割合を切ったとき。収容が `max` 分になっても終わる。満員でも終わる。そのあと撤退で、離脱点に着けば勝ち。
- 乗せた人数で遅くなる（`slowFull`）。
- 着陸・作戦変更・切り上げを起点にした出来事（`landEvents`、`evacEvents`、`doneEvents`）。`wave:true` の出来事は、切り上げ（か満員）のときにまだ来ていなければ捨てる（収容の圧力を絶やさない波を、撤退に持ち込まない）。
- 場面の会話（`evacLogs`、`doneLogs`、`fullLogs`）は、`playScene` で戦闘を止めて見せる。通知だけだと3件しか残らず、大事な台詞がすぐ消える。
- 会話の中の `{boarded}`（乗せた人数）、`{remain}`（残った住民）、`{lost}`（本軍の戦艦の帰らなかった割合。「7割」。離脱点から抜けた隊は帰ったと数える）は、表示するときに埋まる（`fillText`）。

### 段階の始めに艦を預かる（第5節）
`phases` の段階に `given:[艦隊]` を書くと、その段階の始めに自軍の一覧の最後へ足す（`op.given` と同じ。戦区軍の外、研究は効かない）。第5節の総攻撃の、工廠で修理の済んだフリゲート8隻。

### 出来事で隊の動きを変える
`events` の `ai:{fleets, ai, leash, spare, keepOut, log}` で、名前を挙げた隊の動きを変えられる。友軍は `mode` が変わる。`log` は、その隊が一つでも残っているときだけ出す（沈んだ隊の台詞が出ない）。

### 動きの種類
| 名前 | 動き |
|---|---|
| `hunt` | 見えている敵をどこまでも追う |
| `guard` | 持ち場から `leash` 以内だけ相手にする。友軍は、ほかの友軍の3割より多くが狙っている敵を避けて目標を分け、同じ敵には別の向きと高さから挟む（`docs/menu.md`「友軍 AI」） |

### つまずいたこと
- **母艦の位置を直すのは、岩と区画から押し出したあとに**（2026-10-22、小型機と母艦をつなぐ）。岩にもぐる経路を進む揚陸艦は、つないだあとで岩の外へ押し出され、W.A.S. を発艦の距離の外に残していた（第5節で1回に0〜2回、30 を 1.2 倍まで）。`tetherCarriers` は `keepOffBody`・`keepOutOfZones` のあとに呼ぶ。前は、小型機が目標から目標へ渡り歩いて母艦から発艦の距離の5倍（約170）まで離れ、第5節では揚陸艦が W.A.S. を残したまま輪へ降りていた。
- **前に出た持ち場と `leash` だけの友軍は、後ろへ回り込んだ敵に何もしない**（第5節、2026-10-20。東の友軍が持ち場（z 約−20）に残り、揚陸艇と強化歩兵がゲート（z 約150）のシールドを削っても leash 60 の外で、敵が場にいる時間の8〜9割を撃たず動かずにいた）。守る物（ゲート）のまわりに受け持ちを置き、戦線が崩れたら持ち場を下げる（`op.allyFall`）。
- **歩兵の組を中心までの距離で測る**と、射程の中に1人見えていても撃たなかった。組はいちばん近い1人か中心の近いほうで測る（`troopGap`）。艦の高さが岩から射程より離れていれば、真上にいても届かない。
- **覚えていた攻撃目標（`f.strike`）を消し忘れる**と、「もう撃たない」にしたあとも、前の目標を撃ち続ける。
- **`prey` の一覧が `spare` の除外を素通りしていた**。狙わない相手を足し直すときは、`spares()` を通す。
- **一番近いものを守らせると偏る**（4隊が同じ居住区へ行った）。受け持ちはデータで決める。
- 友軍が相手を失うと持ち場（出撃位置）へ戻り、「後ろに下がった」と言われた。`hold` を付ける。
- **友軍がみな持ち場にいちばん近い敵を選び、まっすぐ寄っていた**ので、一か所に固まった（第4節の奪還で6隊が同じ守備隊へ。敵が2つ見えていても95%の時間で全隊が同じ敵）。目標は割合で分け（`ALLY_SHARE_MAX`）、寄る向きを分ける（`allySlot`）。敵が1つしか見えない時間が長い作戦では、分け方より寄る向きと間隔が効く。
- **友軍は寄る向きを自分の持ち場の側（90度未満）に抑えていた**ので、同じ敵を狙っても挟撃にならず、高さもそろっていた。同じ敵を狙う隊は1つの基準の向きを分け合い、0／±115／180度に、上下25〜30度に分かれる（`allySlot`、敵の `slotOf` と同じ考え）。
- **`hold` の友軍は、相手がいなくなるとその場で止まっていた**ので、待つ場所が戦った場所しだいで、居住区から離れたり（区画の縁から平均18〜31）、区画の中に立ったり（待つ時間の4〜11%）、2〜3隊が同じ場所に固まったりした。居住区ごとに外側の縁の外へ、2隊ずつ分ける（`waitSpot`）。

## 6.5 背景の地球・月・火星（ユーザー決定 2026-10-11、入れた 2026-10-12）

- 場の「上」は、月の軌道の北極から地球の向きを軸に20度傾けた（ユーザー決定 2026-10-12。0度だと太陽と火星がいつも地平線すれすれで、艦が下から照らされる）。
- 値（`wos-story` が直した日付で計算、2026-10-12。2099年: 新月 04.19、上弦 04.28、満月 05.04ごろ、火星の衝 2099-10-18）:

## 6.6 戦場より大きな天体（第5節フェブルアーリア、2026-10-12）

- `body.c` で中心を場の外（南の下、(0,-175,250)）に置き、`sq`（3軸の比 1:0.36:0.42）、半径520（持ち場が西へ移るので東西に長い）。戦場の平面は岩の上のほうを切り、総基地は北の斜面にある。上から見ると南の端が弧になる。
- 全体を作ると重いので、戦場に向いた側だけを作る（`face` の向きのまわり `faceA` ラジアン、`SphereGeometry` の帽子を `seg` の細かさで）。`IcosahedronGeometry(1,56)` だと半径400では粗すぎる。
- 裏側（2026-10-15、ユーザーの頼み: 裏側も作る）: 残りの面も、前の面の3分の2ほどの細かさの格子で作る（`bodyShape.back`）。前の面の縁と同じ点の数で始め、つなぎ目の法線をそろえて線が出ないようにした。見るだけで、光線（`bodyHit`）と押し出しは今のまま前の面と `R` を使う。ふだんの視点では前の面に隠れ、遠くへ引いたときや下から回り込んだときに見える
- 大きな岩用のつまみ: `pits`（クレーターの数）、`pitA`（大きさの倍率）、`crag`（突起の高さと鋭さ。ユーザー: 突起はもっとあってもよい）、`fine`（細かい凹凸。大きくすると近くで階段のように見える）、`craterA`（施設のクレーター。小さく）。
- 中心が原点でなくなったので、表面の計算（`bodySurface`、`bodyHit`、`keepOffBody`、見通し、回り込み）はみな `bodyC` からの向きで測る。回り込みの「下をくぐる」案は、場より大きな天体では岩の中になるので捨てる。
- 降下点（`op.landing.points`）は施設（`blocks`）の真上 `up` の高さに自動で置く。輪は青（無事）→ 琥珀（揚陸中）→ 赤（占拠）。
- 地表の味方の砲台は、友軍の `fixed`（第4節の対空砲台と同じ形、色は青）。射程の中の突撃揚陸艦を先に撃つ。岩の表面は戦場の平面より40〜70下にあるので、射程は60にした。
- 持ち場の段階（`op.phases`）: 中心が滑ると `shiftView` でカメラも動く。外に残った艦は `keepInFieldSoft` で、滑っているあいだは引きずらず、そのあとはそれより外へ出さない。持ち場どうしは160〜180離す（研究前の艦は速さ3.5なので、移るのに作戦の時計で2〜3時間かかる）。敵の出る場所は前の持ち場に重ならない向きにする（重なると、移る前の艦が囲まれる）。

## 8. ユーザーの好み（見た目と配置）

- 見た目は、必ず見本の画像を見せて「ok」をもらってから入れる。前後の比較を並べると返事が早い。
- 岩はいびつで、ゴツゴツ（割れた面、クレーター、盛り上がり）。なめらかな球はだめ。
- 建物は小さく、数を多く。丸いチューブでつなぎ、橋は上だけ。砲台も小さく、付け根は地面にぴったり。
- 町はクレーターの中にあり、溝と内部のトンネル（鉄道）でつながる。一か所は露天掘りの鉱山。
- 配置は世界設定に照らして自然に（地球の軌道上か、月より遠いか）。距離は近めから始める。
- サブエージェントに「ストラテジーゲームとして適切か」を評価させると、問題（偏り、棒立ち、台詞と動きのずれ）が具体的に出る。直す前に、ユーザーの決定と食い違う点を選択肢にして聞く。
