# 地上のコードの作りの見直し（第二章の前に）

2026-11-12、ユーザーの依頼で Claude（Fable 5.2）が見直した。第二章（`docs/chapter2.md`）を載せる前に、何を整理しておくかの判断。書き換えそのものは Codex か Opus に渡す。ここに書いた新しいファイル名はすべて仮。

## 1. 結論

第二章は、演習のほかに地上の作戦が6つある。作戦ごとに地図が違い、勝ち方が違い（遅滞、増援まで持ちこたえる、川で食い止める、二正面、上陸）、途中で出来事が起きる（増援、敵の降下、天候、W.A.S. の配備）。今の地上のコードは「地図1つ、出来事なし、勝ち方3種類」の演習のために作ってあり、このまま6つ載せると作戦ごとの特別扱いがコードに積み上がる。

先に整理するのは次の4つ。上から順にやる。

| 順 | 整理すること | 今のまま進めたときに困ること |
|---|---|---|
| 1 | 規則と地形を分ける | 地図を足すたびに規則の写しが増える。天候や作戦ごとの違いを置く場所がない |
| 2 | 作戦データの部隊の書き方を km にそろえる | 地図の大きさを作戦データの式に埋めている。増援や降下でも同じ式を書くことになる |
| 3 | 地上の「台本」を作る（出来事と勝敗をデータで書く） | 時間で起きる出来事が地上では動かない。勝ち方は3種類がコードに直書き |
| 4 | 地形の検査の道具を作る | 架けられない川、つながらない補給、色の違う隅を、遊んでから見つけている |

あわせて、テストを分野ごとに分ける（5.）。これはどの順番でもよく、早いほど得をする。

やらないと決めたこと: 宇宙と地上のコードを大きく2つに分ける書き換え（6.）。

## 2. 規則と地形を分ける

**今**: 兵科の表、戦闘、補給、占領、移動、輸送、上陸、工兵、視界、地点攻撃、高度の段の規則が、地形のファイル `data/terrain/exercise2.js` の中にある。`data/terrain/baikonur2.js` と `data/terrain/wide-fields.js` は、12個の規則を名前で並べて写している。自軍の地上編成（`data/ground-org.js`）は、隠し作戦 `groundExercise2` の部隊と `exercise2` の兵科の表を直接読んでいる。

**困ること**: 規則を1つ足すたびに、写しの一覧を全部の地図で直す（忘れると、その地図だけ規則が欠ける）。作戦ごとの違い（第5節まで W.A.S. なし、雨で視界と足が変わる）を書く場所がない。今日の「バイコヌールだけ架橋の上限を変える」は、たまたま地形の側の値だったので書けた。

**決めること**:

- 規則は1つのファイル（仮: 地上の規則のデータ）に置く。地形のファイルは地形だけ（地図の大きさ、標高、川、道、橋、拠点、森、建物）。
- 規則を読む入口を1つにする。順に重ねる: 基本の規則 → 地形の上書き（その土地だけの値。川幅の上限など）→ 作戦の上書き → 試合中の変化（天候）。今も `groundSupplyRules()` のような入口の関数を通っている所が多く、地形から直接読む所は約20か所なので、今なら小さい。
- 自軍の地上編成は、隠し作戦ではなく規則のデータから既定の編成を作る。

**大きさ**: 小〜中。動きは変えない。全部のテストが今のまま通ることで確かめる。

## 3. 作戦データの部隊の書き方

**実装 2026-11-14（Codex、レビュー前）**: 作戦データ（`data/operations.js`）の部隊は `{name,kind,at:[xKm,yKm],band?}`。艦種・揚陸・搭載中隊も同じ形式。`battle/terrain.js` の `groundUnitSpec()` だけで既存の艦隊の形へ直す。案内の印は `at`、初めの視点は `view.targetKm`。旧形式の道具や固定配備も引き続き使える。

**整理した理由**: 地図ごとに式が必要で、増援や降下（次の節の台本）にも広がるため。

**出撃**: 編成には位置を保存しない。`groundSortie` の枠または拠点周辺へ `groundSortieForces()` が配置し、`maxCompanies` と `bannedKinds` を適用する。兵科の通行判定を使い、拠点周辺の地上部隊は川にも置かない。制限は編成出撃だけに効く。

**範囲**: 票3で実装。台本による増援は票4でこの書き方を使う。

## 4. 地上の台本（出来事と勝敗）

**今**: `battle/sim.js` の1ステップは、地上なら初めに `groundStep()` を呼んで戻る。宇宙の出来事の仕組み（時刻で増援・通信・段階の切り替え）は、その先にあるので地上では動かない。地上の勝ち方は `battle/ground.js` に3種類（全拠点の占拠、敵本営の占領か全滅、案内の完了）が直書きで、負けは自軍の全滅だけ。

**第二章で要るもの**（`docs/chapter2.md` の各節から）:

| 節 | 要る出来事と勝敗 |
|---|---|
| 1 中東・遅滞 | 敵の増援が次々に着く。決めた時刻まで持つ、または決めた数の隊を出口へ逃がせば勝ち |
| 2 中東・防衛 | 友軍の増援が時刻に着く。それまで本営を守れば勝ち |
| 3 華南・川 | 敵の波。橋と川の線を時刻まで保つ |
| 4 広州前面 | 敵が後ろへ降下する（予告つきで空から出る）。前と後ろの二正面 |
| 5 広州 | 守り切る。終わりに W.A.S. が配備される |
| 6 海岸・上陸 | 上陸、海戦、艦砲。拠点を取り、敵を逃がさない |

**決めること**: 地上専用の小さな台本の層を作る（仮: 地上の台本のファイル。`battle/sim.js` の出来事の処理へ地上を戻すのではなく、地上の側に置く）。作戦データに次の3つを書く。

- **きっかけ**: 時刻、拠点の持ち主が変わった、拠点を失った、ある軍の力が割合を切った、ある軍が円に入った、旗が立った、別の出来事の何秒後。`all`（全部）と `any`（どれか）で組める。
- **すること**: 部隊を出す（地図の端から、空から降下、海から。出た隊は指揮官に入る）、通信を出す、目標の文と勝敗の条件を変える、指揮官の意図を変える（`docs/npc-doctrine.md` 9.7 の seize・hold・delay・withdraw）、拠点の持ち主を変える、天候を変える、旗を立てる、地図に印を出す、出口を開く、勝ち・負けで終える。
- **勝ちと負けの条件**: きっかけと同じ部品で書く。足す部品は、拠点を時刻まで保つ、決めた数の隊が出口から出た、ある軍が全滅した、時刻になった。今の3種類の勝ち方も、この部品で書き直す。

宇宙の出来事の書き方（`after` 分、通信の `log`）と言葉をそろえるが、コードは共有しない。宇宙の出来事は作戦ごとの特別扱いが多く、地上を合流させると両方が壊れやすくなる。

**大きさ**: 中〜大。部品の一覧（上の3つ）を先に資料で固め、演習1つ（増援と降下と時刻の勝ち）で試してから第二章へ進む。ここが6つの作戦すべての土台になる。

## 5. 地形の検査の道具とテストの分け方

**地形**: 地図は3つあり、作り方が3通り（値を直書き、規則を写して組み立て、生成）。第二章であと6つ要る。作る手順はそのままでよいが、できた地図を検査する道具を1つ作る。見るもの:

- 拠点が道路に載っている、両軍の本営が道路でつながる、橋が川の上にある
- 兵科ごとに、本営から本営まで通れる道がある
- 工兵が架けられる所と、揚陸艦が着ける浜が、どこにどれだけあるか（一覧で出す）
- 盤の端と海の塗りに、地面の色が出ていない
- 重さ: 経路探索と視界の1回の時間が、決めた上限に入る

今日ユーザーが遊んで見つけた3つ（上の方の川に架けられない、補給がつながらない、南の隅が陸地）は、この検査で先に分かる種類のもの。

**テスト**: 今は `tests/smoke.cjs` が37ファイルを1本で回し、CI は約17分かかる。宇宙・地上・NPC の3つに分けて並べて走らせ、手元では分野を選んで走らせられるようにする。どの PR も待ちが短くなるので、早くやるほど得をする。地上の作りには触らない。

## 6. やらないこと、後でよいこと

- **宇宙と地上を大きく2つに分ける書き換えは、しない。** 共通の本体（`battle/sim.js`）と地上の分かれ目は、ステップ・視界・移動・損害・表示の14か所だけで、すでに細い。地上は初めに自分の処理へ抜ける。ここを書き換えても第二章は楽にならない。
- **画面のコード**（`battle/hud.js` に34か所、`battle/state.js` に30か所の地上の分かれ目）は、今は分けない。第二章で増える画面は少ない（天候の表示、降下の予告）。決まりを1つだけ置く: 地上の新しい画面は地上のファイルに書き、共通の2つに分かれ目を足さない。
- **`battle/ground.js`**（勝敗、占領、部隊の一覧、表示、ステップが一緒）は、台本を作ると勝敗がそちらへ移り、そのぶん軽くなる。残りは触るときに分ける。
- **部隊の状態**（部隊に付く地上用の値が53種類）は、今は困っていない。やり直しや出来事で部隊を出すときの初期化だけ、台本を作るときに1か所にまとめる。
- **重さ**: バイコヌール演習（96×72 km）で1ステップ平均4ミリ秒。第二章の地図はこの大きさを上限の目安にし、もっと広くするときに測り直す。

## 8. 作業票（Opus が実装する）

上から順に、1票を1つの PR にする。どの票も、今ある作戦の動きと数値は変えない（変えるものは票に書く）。終わったら `npm test` を通し、`docs/PROJECT_STATUS.md` とこの資料の該当する票に「実装」と日付を書く。分からない所は推し量って作り込まず、ユーザーに聞く。

### 票1: テストを分野ごとに分ける

- **ねらい**: PR ごとの待ちを短くする。今は `tests/smoke.cjs` が37ファイルを1本で回し、CI は約17分。
- **やること**: 宇宙・地上・NPC の3つに分け、手元で分野を選んで走らせる命令（`npm run` の名前）を足す。`npm test` は今までどおり全部を順に回す。CI は3つを並べて走らせる。
- **気をつけること**: マージの条件が CI の「smoke」という名前の確認に付いているかを先に見る。付いていれば、名前を残すか、条件を直す手順をユーザーに伝える。手元では、ブラウザを使うテストを同時に2つ走らせない決まりは変えない。
- **確かめ方**: 分ける前と後で、確認の総数が同じ。CI の時間を前と後で書く。

### 票2: 規則と地形を分ける

実装 2026-11-14（Codex が実装し Claude がレビュー。新しい規則のファイル `data/ground-rules.js`、入口 `groundRuleSet()`）

- **ねらい**: 2. のとおり。地図を足しても規則の写しが増えず、作戦と天候で規則を上書きできる。
- **やること**:
  - `data/terrain/exercise2.js` にある規則（高度の段、視界、地点攻撃、輸送、上陸、工兵、兵科の表、艦砲の射程、戦闘、占領、移動、補給）を、新しい規則のデータのファイルへそのまま移す。地形のファイルには地形だけを残す。`data/terrain/baikonur2.js` と `data/terrain/wide-fields.js` の「規則を名前で写す」行を消す。
  - 規則を読む入口を1つ作る。重ねる順は 基本 → 地形の上書き → 作戦の上書き → 試合中の変化（天候用。今は空）。重ねた結果は作戦の開始時と変化のときだけ作り直し、同じものを返す（移動や占領は1ステップに何度も読むので、読むたびに重ね直さない）。

- **触らないもの**: 規則の値、`battle/npc-core.js`。
- **確かめ方**: テストの期待値を変えずに全部通る。`node tools/npc-sim.cjs baikonur mars earth standard 1 300 --brief` の出力が、前と後で同じ。試遊ページに載せる手順（`.claude/skills/ship/SKILL.md`）にファイルの一覧があれば直す。

### 票3: 部隊の書き方をそろえ、編成した部隊で出撃する

- **実装 2026-11-14（Codex、レビュー前）**。ユーザー決定（同日）: バイコヌールの「クイック出撃」は決まった11隊、「出撃する」はプレイヤーの地上編成。両方の出撃に数・兵科の制限は付けない。
- `tools/ground-start-snapshot.cjs` で変更前に5種類の開始状態と1600×900の写真を保存。`tests/ground-forces.cjs` が固定配備4種類を実測の写しと比較し、編成出撃をAから8km以内・通行可能と確認する。既存の配置画面は地上部隊を本営内へ並べ直すため、開始直後の地上部隊の間隔は既存処理による。航空隊も作戦側の出撃地点に置かれる。

- **ねらい**: 3. のとおり。あわせて、ユーザー決定（7. の 1）を入れる。
- **やること**:
  - 作戦データの地上の部隊を「名前・兵科・km の位置・高度の段」で書く。海の艦は、艦の種類・揚陸艦かどうか・積んでいる部隊も同じ書き方。画面の座標と艦隊の形（今の `type:'cv',n:1,scale:.3`）へ直すのは、地上の側の1か所だけ。`data/operations.js` の `(x-24)*4` のような式と、地図ごとの関数をなくす。案内の印と初めの視点も km で書く。
  - 早送りの道具とテストで同じ式を持っているものは、同じ入口か `groundPoint()` を使う。画面の縮尺（4）と地図の半分の大きさを知っているのは `battle/terrain.js` だけにする。
  - **出撃**: 編成を固定しない地上の作戦では、プレイヤーの地上編成の中隊が出る。今は出る位置を隠し作戦の配置から借りているので、作戦データに出撃地点（拠点か、km の位置と半径）を書き、そこへ兵科が通れる地面に並べて置く。そのあと今の配置の画面で動かせる。作戦ごとに、持ち込める中隊の数と、使えない兵科を書けるようにする（第5節の終わりまで W.A.S. なし、など）。損害は持ち越さないので、保存するのは編成だけで今のまま。
  - 編成を固定するチュートリアル2は、今の部隊の一覧のまま。隠しの地上演習は編成出撃の従来の枠を維持する。
- **決定済み**: 上記のクイック／編成の2つの入口を使う。
- **確かめ方**: 作戦の初めの部隊の位置が、前と後で同じ（決まった部隊の作戦）。編成した部隊が、川や海や盤の外に置かれない。

### 票4: 地上の台本（出来事と勝敗）

実装 2026-11-14（Codex、レビュー前）。部品と確定した範囲は `docs/ground-script.md`。勝敗は毎ステップ、出来事だけ0.5ゲーム秒ごと。天候と友軍としての増援は後で。

- **ねらい**: 4. のとおり。第二章の6つの作戦の土台。
- **作り**: 2つに分ける（指揮官の頭と橋渡しと同じ考え方）。
  - **判定**: 台本と「今の状態」（時刻、拠点の持ち主、軍ごとの力と初めの力、円の中にいる隊、出口から出た隊の数、立っている旗、済んだ出来事）だけを読み、「起こすこと」の一覧を返す。画面や戦闘の内部に触らないので、Node だけで試せる。
  - **適用**: 状態を作り、「起こすこと」を実際に行う。判定は毎ステップではなく、ゲーム内の0.5秒ごと。やり直しで初めに戻る。
- **作戦データ**（名前は仮）: `groundScript` に `win`、`lose`、`events`（`id`、`when`、`do`、1回だけか）を書く。
  - **きっかけ（when）**: 時刻 / 拠点の持ち主 / 拠点を失った / ある軍の力が初めの何割を切った / ある軍が円に入った / 旗 / 別の出来事の何秒後。`all` と `any` で組む。
  - **すること（do）**: 部隊を出す（票3の書き方。地図の端から入る、空から降下、海から。降下は予告の印と秒数、降りている間は被弾が増える）/ 通信 / 目標の文と勝敗の条件を変える / 指揮官の意図を変える / 拠点の持ち主を変える / 天候を変える（票2の「試合中の変化」へ入れる。中身は `docs/weather.md` が決まってから）/ 旗 / 地図の印 / 出口を開く / 勝ち・負けで終える。
  - **勝ちと負け（win・lose）**: きっかけの部品に加えて、拠点を時刻まで保つ / 決めた数の隊が出口から出た / ある軍が全滅 / 時刻になった。
  - 出した部隊は、その軍に指揮官がいれば自動で指揮官の隊になる。友軍として出す部隊は、友軍の指揮官（`docs/npc-doctrine.md` 5.）が動かす。
- **今の勝ち方**: 3種類（全拠点の占拠、敵本営の占領か全滅、案内の完了）は、今の書き方のまま動くようにし、中では台本の部品へ直して判定する。負け（自軍の全滅）も同じ。
- **試す場所**: デバッグで開く隠しの演習を1つ足す（チュートリアル2の地形）。60秒に敵の増援が東の端から入る、120秒に本営の後ろへ予告つきで降下、300秒まで本営を保つか敵を全滅させれば勝ち、本営を失うか全滅で負け。数値は仮。
- **触らないもの**: `battle/sim.js` の宇宙の出来事の処理、今ある作戦の勝敗。
- **確かめ方**: 判定の Node のテスト（部品ごと）と、試す演習のブラウザのテスト。今ある地上の作戦の勝ち負けが変わらない。

### 票5: 地形の検査の道具

- **ねらい**: 5. のとおり。第二章の地図を、遊ぶ前に検査する。
- **やること**: 地形1つを読み、5. の一覧（拠点と道路、本営どうしの道、橋、兵科ごとの通行、架けられる所と着ける浜の一覧、端と海の塗り、経路探索と視界の時間）を調べて表で出す道具を作る。今ある3つの地形にかけ、見つかった問題を報告する（直すかどうかはユーザーに聞く）。ブラウザなしで走る検査は CI に入れる。
- **確かめ方**: わざと壊した地形（拠点を道路から離す、橋を川から外す）で、検査が落ちる。

- **実装 2026-11-14（Codex が実装し Claude がレビュー）**: `tools/terrain-check.cjs` と `tests/terrain-check.cjs`（ground 組）。4地形を対象に、作戦の `groundHQ`（チュートリアルの上書きも含む）を調べる。道路は0.2km刻み・0.3km以内を連結。架橋は川の中心線をセル幅ごとにたどり、実際の `groundBridgePlan` で判定する。浜は海セルの陸8近傍、連続区間も8近傍。塗りは盤の外接長方形をセル半幅で走査し、地形の格子の矩形または海で覆われるかを見る（セル値の有無とは別）。四隅は外接長方形の四隅を陸・海と盤内外で併記する。
- **性能の仮上限**（2026-11-14、baikonur2 の Chromium 実測×1.5、ms）: `reset({op:'baikonur'})` で固定配備を作り、停止後に探索・高さのキャッシュを消して各10回。1回目を初回、2〜10回目を再利用として分ける。探索は本営A→Fの車両、視界は `groundUpdateSight()`。CI には入れない。値は端数を丸めており、別の実行環境では再評価が必要。
