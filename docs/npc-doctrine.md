# NPC の規範行動（指揮官の層）

宇宙と地上で共通の、敵と友軍の「指揮官」の設計。2026-11-11、ユーザーの依頼で Claude（Fable 5.2）が設計した。数値はすべて仮で、表は `data/npc-doctrines.js`。頭は `battle/npc-core.js`。

## 1. ねらいと決まったこと

今の AI は「隊ごとの動き」（狙いの分担、挟み撃ち、艦種別の動き、射程に入れば撃つ）だけで、**作戦全体の判断**がない。陽動や増援は作戦ごとのデータに手で書いている。ここで作るのは、その上に載る指揮官の層。

ユーザー決定（2026-11-11）:

- 宇宙と地上で同じ設計にする。今後の更新を見越した土台で、今ある作戦には入れない。作戦ごとに有効にする（`roleAI` と同じ考え方）。
- 例外はバイコヌール演習で、最初にこの AI で敵を動かす。2026-11-11の追加指示で、案内なしのカリュブディス演習も試験場にする。チュートリアル2は有効にせず、敵は動かず撃たない。
- 敵だけでなく友軍も対象。友軍は脇役で、勝ちすぎない制限を付ける。
- 規範は一つ。強さの段階は、判断の速さと読みの深さだけで付ける。
- 連合と共和国は、地上でも戦い方を変える（案は 4.）。
- NPC はプレイヤーと同じ視界を使い、同じ命令を出す（ずるをしない）。
- バイコヌール演習の勝利条件は「敵基地の占領、または敵の全戦力の撃破」。
- 守り方の型は4つ（固守・遅滞・機動防御・縦深）。既定は連合が固守、共和国が機動防御。本営はどの型でも捨てない。
- 本番のマップはバイコヌール演習（48×36km）よりかなり大きくなりうる（150×100km、300×200km）。その大きさで動くこと。

## 2. 形

```
状況（sit）──▶ 頭 npc-core.js ──▶ 任務の一覧（plan）
   ▲                                   │
   └── 橋渡し npc-ground.js／npc-space.js ◀┘   任務を通常の命令に直す
```

- **頭**（`battle/npc-core.js`）: 状況だけを読み、任務だけを返す。three.js・画面・戦闘の内部に触らないので、Node だけで試せる。宇宙と地上で同じものを使う。
- **橋渡し**: モードごとに1つ。戦闘の状態から状況を作り、任務をプレイヤーと同じ命令（移動・攻撃など）に直す。戦闘の内部の値は書き換えない。
- **規範**（`data/npc-doctrines.js`）: 陣営ごとの性格と、強さの段階。頭はこの表だけで性格が変わる。
- 有効にする書き方: 作戦データに `npc:{1:{doctrine:'mars',level:'standard'}}`（キーは軍の番号。友軍は `side:'ally'` を足す）。書いていない作戦では何も動かない。

こうしておくと、あとでコードを宇宙と地上の2つのモードに分けても、頭はそのまま使える。

## 3. 頭の考え方

指揮官は、拠点（zone）とそのつながり（link）で戦場を見る。1隊ずつ地図を探索しないので、広いマップでも重くならない。考えるのは数秒に1回（強さの段階で決まる）。

1. **見積もる**: 自軍の力、知っている敵の力、その比。拠点ごとの脅威（近い敵ほど強く数える）。敵地をどれだけ最近見たか。見失った敵は、位置だけが時間とともに薄れ、数は覚えている（力の比には数え続ける）。見ていない敵地には守備がいると仮定する。
2. **姿勢を決める**: 攻める・守る・遅滞（下がりながら守る）・偵察。力の比で決める。行ったり来たりしないよう、境目に幅を持たせ、変えるまでに反応の遅れを置く。
3. **任務を立てる**:
   - 守り（hold）: 本営と、前線か脅威のある拠点。攻めているあいだは守りを節約する。守りの姿勢でも、取られた拠点の取り返しと、隣の守りの薄い拠点（中立など）は余力で取りに行く。
   - 主攻（seize）: 目標の拠点を点数で選ぶ（作戦の目標、近さ、守りの薄さ、補給線を切れるか、取られた拠点か、最近失敗した所は避ける）。そこへの経路の、最初の敵地を取りに行く。
   - 助攻（fix）: 主攻と別の拠点の敵を、突入せずに押さえつける。
   - 遮断（cut）: 敵の本営と前線のあいだの、守りの薄い拠点を取る。
   - 偵察（recon）: 長く見ていない敵地へ。
   - 予備（reserve）と再編（refit）。
4. **隊を割り当てる**: 拠点を取れる隊は少ないので、先に攻めの任務へ1つずつ確保する。そのうえで大事な任務から順に、着くのが早く役の合う隊で埋める。今の任務を続ける隊を優先し、ころころ変えない。士気か補給が減った隊は下げて休ませる。耐久が減った隊（休んでも戻らない）は攻めの最後に回し、守りと予備に使う。火力・打撃・護衛・支援の隊は、主攻（なければ脅威のある守り）に付ける。
5. **段取りを進める**: 主攻は 集結 → 前進 → 突入。集まる前に攻めない。前進は目標の手前（攻撃の位置）までで、主攻がそろってから一斉に突入する。突入してしばらくたち、その場の敵に力で負けているか、隊を失ったら中止して下がり、しばらくその拠点を避ける（経路でも避け、ほかに道がなければその方向へは攻めない）。取りに出た拠点は、見積もりが少し揺れたくらいでは変えない。

動きに理由があり、集結という前触れがあるので、プレイヤーは意図を読んで裏をかける。拠点の点数には隊ごとの小さなゆらぎを入れ、毎回少し変わる。指揮官は判断の理由を記録する（`log`）。

役は7つ: 線（line）、突破（shock）、火力（fires）、護衛（screen）、偵察（recon）、打撃（strike）、支援（support）。兵科・艦種との対応は `data/npc-doctrines.js` の `roles`。

## 4. 陣営の性格（仮）

| | 地球連合 | 惑星共和国 |
|---|---|---|
| 考え方 | 火力と線。集めてから一方向を押す | 機動と浸透。固い所を避けて回り込む |
| 攻め始める力の比 | 1.5 | 1.1 |
| 主攻に集める割合 / 予備 | 7割 / 25% | 5割 / 10% |
| 集結 | 8割集まるまで待つ | 6割で出る |
| 助攻・遮断 | 出さない | 出す（補給線を切りに行く） |
| 経路 | 最短を通る | 守りの固い拠点を避ける |
| 取ったあと | 30秒固めてから次へ | 10秒で次へ |

宇宙の性格（連合は大艦巨砲、共和国は W.A.S. が要。ユーザー決定 2026-10-22）と同じ向き。

強さの段階（規範は同じ）:

| | やさしい | 標準 | 難しい |
|---|---|---|---|
| 考える間隔 | 6秒 | 3秒 | 1.5秒 |
| 姿勢を変えるまでの遅れ | 12秒 | 5秒 | 2秒 |
| 見失った敵を覚えている時間 | 30秒 | 60秒 | 120秒 |
| 脅威として数える距離（マップの差し渡し比） | 0.25 | 0.5 | 0.8 |
| 同時の攻めの任務 | 主攻だけ | ＋助攻 | ＋遮断 |
| 敵の力の見積もりの誤差 | ±40% | ±20% | ±5% |

## 5. 友軍

友軍は、プレイヤーの作戦の脇役。攻めるかどうかを自分の力の比では決めず、先導（プレイヤーの隊）の動きを読んで合わせる。2026-11-12、Claude（Fable 5.2）が設計し、頭に入れた。数値は仮で、表は `data/npc-doctrines.js` の `ally`。画面とのつなぎ（5.3）は2026-11-12に実装。ブラウザの確認・実測はClaudeへ引き継ぐ。

### 5.1 決まり（前からのもの）

- 作戦の最終目標（`final` の拠点）は取らない。
- 先導の先頭の拠点より先へ出ない。先頭は `sit.lead.front` の指定、なければ味方の拠点と先導のいる拠点のうち、本営からいちばん遠い所。
- 取られた拠点の取り返しは自分からは始めない。

### 5.2 先導に合わせる動き（`sit.lead.units` を渡したときだけ働く）

橋渡しは、先導の隊を `sit.lead.units`（`id`・位置・`power`・命令先の拠点 `to`）で渡す。同じ軍なので、位置と命令先は知っていてよい。先導の初めの力を `sit.lead.full` で渡せる（省略すると、頭が見た中の最大を使う）。

- **読む**: 先導の力の3割以上（`main`）が向かっている、味方のものでない拠点を「先導の攻撃目標」と見る。命令先がない隊は、拠点のそば（半径の2.5倍）にいればその拠点に数える。
- **姿勢**: 力の比は友軍と先導を足して数える。先導に攻撃目標があれば「攻める」、なければ「守る」。比が低ければ遅滞。切り替えには強さの段階の反応の遅れがかかる。
- **引き継ぎ**: 守備の要る力から、その拠点にいる先導の力を引く。先導がいる拠点には守備を重ねず、離れたら置く（理由は「引き継いで守る」）。
- **支援攻撃**: 先導の攻撃目標へ、助攻（`fix`）と同じ動きで出る。手前で止まって撃ち、占領の円には入らない。押し返された拠点は `retry` のあいだ避ける。
- **空いた拠点**: 敵の見積もりが平均的な1隊の半分以下（`easy`）で、味方の拠点の隣にあり、先頭より先でなく、先導が向かっていない拠点だけ取る。見ていない敵地には守備がいると仮定するので、見て空だと分かった所か中立に限られる。
- **控える**: 攻めに出す力は、線と突破の隊の半分まで（`commit`）。主攻に兵力を集める規範の値（`mass`）は使わない。助攻と遮断は出さない。
- **とどめを残す**（`quiet`）: 知っている敵の力が、いちばん多かったときの2割（`finish`）を切ったら、攻めの任務をやめて守りに戻る。
- **助けに入る**（`rescue`）: 先導の力が初めの半分以下（`rescue`）になるか、本営を失ったら、制限をゆるめる。姿勢は自分で決め、先頭より先へ出てよく、取り返しもする。最終目標だけは取らない。
- **記録**: 切り替えを `ally:follow`・`ally:quiet`・`ally:rescue` で log に残す。`plan.lead` に攻撃目標・今の状態・先導の力を入れる。

`sit.lead.units` を渡さない友軍は、5.1 の決まりだけで今までどおり動く。

### 5.3 オートモードとのつなぎ（実装、ユーザー決定 2026-11-12）

ユーザー指示（2026-11-12）「オートモードをオンにしているとき、演習でこれのテストをする。オートモードはメニューから試合中でもオンオフできるように」。下の形で決定。とどめを残す・助けに入る（5.2）も入れる。

**オートモードは試すための道具で、本番ではプレイヤーの軍にオートモードはない**（ユーザー決定 2026-11-12）。本番で友軍の頭を使うのは、作戦に出てくる友軍の NPC だけ。そこでは先導はいつもプレイヤーの全部の隊で、「命令した隊がプレイヤーの隊になる」「20秒で戻る」は関係しない。この2つをゲームの仕組みとして作り込まない。

- オートモードをオンにすると、`npc` のある作戦（バイコヌール演習、案内なしのカリュブディス演習）では、指揮官が自軍（軍0）を動かす。規範は連合、強さは標準。ほかの作戦は今の台本のオート（`autoAI`）のまま。
- プレイヤーが何も命令しなければ、指揮官は全部を制限なしで指揮する（`side` は友軍でない）。
- オートモード中にプレイヤーが命令を出した隊は「プレイヤーの隊」になる。指揮官はその隊に命令せず、`sit.lead.units` として読み、残りを友軍（`side:'ally'`）として動かす。`sit.lead.full` には、今のプレイヤーの隊の、損害を受ける前の力の合計を渡す（隊を出し入れしても「助けに入る」が誤って働かないように）。
- 命令が終わって20秒たった隊は、指揮官に戻る。この自動で戻る動きは無効にできるようにする（無効のあいだ、命令した隊はオートモードを切るまでプレイヤーの隊のまま）。オフにすると全部プレイヤーに戻り、隊は今の命令を続ける。オンに戻すと指揮官を作り直す。
- 友軍が任務を始めたら、通信に一行出す（例「友軍: D を保持する」「友軍: C への攻撃を支援する」）。同じ内容は続けて出さない。
- 測り方: `tools/npc-sim.cjs` に、軍0を「先導役の指揮官」と「友軍の指揮官」に分ける引数を足す。物差しは、友軍が最終目標を取った回数と先頭より先へ出た回数（どちらも0）、占領のうち友軍が取った割合、引き継ぎまでの時間、友軍がいるときといないときの勝つまでの時間の差。

実装（Codex、2026-11-12）:

- デバッグの所属・復帰時計・初期戦力・通信は `battle/npc-ground.js`、宇宙の入力と隊AIの除外は `battle/npc-space.js`。画面の命令入口に `npcAutoPlayer()` を置く。低層の `order()`、敗走、再補給、自動対空には置かない。移動・攻撃・予約・方針・高度・陣形・布陣・進撃計画・範囲攻撃・搭乗・降車・上陸・架橋・補給指定・Undoを対象にする。
- オートの規範は `earth`、段階は `standard`。作戦の `npcAuto:{doctrine,level}` で上書きする。オン直後／最初の判断前の手動命令にも対応。オフは今の命令と予約を保ち、同期速度・守備追撃・持ち場維持のNPC用の記録を外す。再度オンは新しい指揮官。
- 手動の隊は頭の `units` と宇宙の隊AIから除外し、判断ごとに `side` と `lead.units` を作る。`to` は現在の命令先・攻撃先・未実行計画・地点攻撃・補給先から、影響半径の1.5倍内の最寄りの拠点を選ぶ（なければnull）。`lead.full` は所属中の隊の損害前の力の合計。所属中の戦死は分母へ残し、損失として読む。部隊一覧の小文字欄に「手動」と表示する。
- 復帰は `data/npc-doctrines.js` の追加項目 `auto:{returnSec:20}`（仮）。現在命令・予約のほか、未実行計画、斉射、爆撃進入、架橋・上陸、補給指定、高度変更などが終わってからゲーム内20秒。復帰オフ中は所属を保ち、再びオンにしたときは蓄積した待機時間を使う。一時停止のデバッグボタン「自動で指揮官に戻す」と準備画面のデバッグ保存 `wos.debug.autoReturn`（初期オン）で切り替える。通常の進行保存には追加しない。
- 通信は友軍としての保持・引き継ぎ・支援攻撃・確保の開始／段取り・理由の変更と、rescue／quietへの状態変更だけ。予備・再編・偵察は出さない。同文はゲーム内30秒未満では再送しない。宇宙の友軍fixは保有円の外へ持ち場を置き、追撃範囲も円外に限る。敵の従来fixは維持。
- 早送りは `node tools/npc-sim.cjs baikonur mars earth standard 1 600 --ally 0.5 --brief`。割合は隊数で0以上1未満（先導役を残すため）。軍番号は同じ0のまま、先導と友軍の隊・速度同期・道路係・守備記録を分ける。先導の `to` は任務の目標拠点なので、集結中も出発拠点にはしない。既存の地上調整値は変更なし。
- JSONの `ally` とbriefに、友軍が参加した占領回数／自軍の全占領に対する割合、敵本営占領回数、先頭より先への攻め任務の開始回数（seize/fix/cut、rescue中の開始は除外）、引き継ぎ平均秒／到着件数／未着件数、follow/quiet/rescueのゲーム秒割合を出す。共同占領も友軍参加なら1回とし、再占領も数える。先頭は頭と同じ道路距離・味方拠点・先導の近傍2.5r、引き継ぎの開始は先導が前線の自軍拠点の近傍を離れた時、終了は友軍holdの隊が影響円へ到着した時。勝敗・決着の秒は既存の出力を使う。`tools/npc-measure.cjs` は従来15条件＋バイコヌールseed1・600秒の友軍なし／0.5の2条件で全17条件。

**支援攻撃と「先走り」の数え方**（2026-11-12、Claude）: 先導が攻める拠点への支援攻撃（`fix`、占領の円に入らない）は、先導の先頭の一つ先を向くが、5.2 の設計どおり。物差しの「先頭より先への攻めの任務」からは、先導の攻撃目標への `fix` を除いて数える（`tools/npc-sim.cjs`）。指揮官が出す命令は `npcIssuing` のあいだ画面の入口を通ってもプレイヤーの隊にしない（輸送・架橋・上陸のつなぎで、指揮官が画面と同じ命令の関数を使うときのため）。

確認と引き継ぎ: Nodeの地上・宇宙・計測器に確認を追加。`tests/smoke.cjs` は従来の会話自動送り・配置省略・自軍移動の確認を保持し、両演習の実メニューボタン、方針指定、手動表示、復帰と保存の確認を追加。写真台本は `tools/npc-auto-shots.cjs`（1600×900、`.shots/npc-auto/`）。ユーザー指定でChromiumは起動しておらず、600秒の勝敗・占領割合・性能値・写真は未取得。実行はClaudeが写真台本→早送り→全smokeを重ねずに行う。非公開試遊ページは未更新。

## 6. 地上の橋渡し（`battle/npc-ground.js`）

- **拠点**: 作戦の拠点（`groundSites`）。座標は地図の km。半径は拠点の影響円。持ち主は、その軍の視界で見えているときだけ伝える（自軍の拠点は常に分かる）。作戦の説明で分かる初期の持ち主は `known` で渡す。
- **つながり**: 補給の道路網（`groundSupplyNet`）から、拠点と拠点を道路でたどった距離。橋が落ちていれば閉じる。そのため NPC を有効にする作戦は本営（`groundHQ`）を持つこと。
- **隊**: 役、力（兵科の重み × 残りの耐久）、速さ、拠点を取れるか、士気、補給、命令できるか（敗走・搭乗中・基地へ帰投中は不可）、交戦中か。
- **敵**: その軍の接触の記録（`groundContacts`）だけ。見えていない敵の今の位置は使わない。
- **任務 → 命令**: 通常の `order()` と地点砲撃・搭乗・降車・上陸・架橋・補給の既存コマンドだけを使う。目的地が大きく変わったときだけ出し直す。
  - 守り: 拠点を取れる隊は占拠円の中、ほかは脅威の向きに並ぶ。
  - 主攻: 集結は出発拠点の目標寄り、前進は突破の隊が先、突入で占拠できる隊が占拠円へ入り、ほかは見えている敵を攻撃。
  - 助攻: 目標の手前（射程の8割）で止まり、占拠円には入らない。
  - 偵察: 視界の8割の所で止まる。
  - 火力: 目標から射程の7割、味方の側。打撃・護衛: 主攻の上空と後ろ。支援: 主攻の後ろ。
- NPC が動かす軍では、既存の `groundSupplyAI`（敵の自動の補給帰り）は使わず、頭の再編に任せる。地点砲撃の自動（`groundStrikeAI`）と自動対空はそのまま使う。
- 道路: 脅威のない守りか予備の1隊が、本営から自軍の拠点までの道路の区間を占領してつなぐ。主攻の最後尾の隊も、通りながら経路上の区間を取る。再編の隊は、補給が届いている一番近い地点で止まる。
- 火力: 間接火力は、任務の目標の中か主攻の近くの見えている敵へ砲撃する（味方が着弾の範囲にいる地点は撃たない）。
- 輸送・上陸・架橋・補給のつなぎは `op.npcLift:true` の作戦だけで動く（2026-11-14、Codex、レビュー前）。既存作戦とバイコヌールでは無効。
- まだ使わないもの: 布陣・進撃計画の線、揚陸艦以外の海の艦への移動任務。

## 7. 宇宙の橋渡し（`battle/npc-space.js`、2026-11-11 実装）

ユーザー指示（2026-11-11）「宇宙のほうは、要塞攻略演習にその AI の動きを組み込み、試験場にしてよい」。案内なしのカリュブディス演習を対象にした。`npc` があり、地上でも案内中でもない作戦だけで動く。頭・規範値・隊の狙い分担・上下の挟み撃ち・艦種別の動き・艦載機の仕組みは変えない。

- **拠点**: 作戦の `npcZones`。円内（水平距離）に片軍の艦隊だけが連続で仮10秒いれば保有する。固定物・艦載機・退場隊は数えない。競合・無人は時計をリセットし、無人なら以前の持ち主を保つ。要塞を含む本営は要塞生存中その軍のもの。画面には出さない。
- **つながり**: `npcLinks` の無向辺。距離は水平直線距離。カリュブディスの拠点表と16辺、仮の距離は `docs/menu.md`「宇宙NPC」。
- **情報**: 自軍保有は常に分かり、ほかの拠点の現在の持ち主は艦隊の視界で見えた場合だけ。初期の持ち主は作戦で既知の `known`。敵艦隊は `updateFog()` の発見結果だけを記憶し、見失ったら最後の位置・力と時刻を保持する。視界外の死亡では消さない。役は最重量艦種、力は残存隻数×hp×dmgを巡洋10隻で割った値。固定・退避・未到着などは任務を与えない。
- **任務 → 隊の値**: `ai`・`post`・`leash`・`watchPos`を変化時だけ更新する。古い移動や、新しい持ち場の外への攻撃は解除し、通常の `enemyAI()` に任せる。
  - hold: 円の半径をleashとし、水平と高度にずらしてguard。
  - seize: 集結は出発拠点でguard、前進は目標のr＋射程の手前でguard、突入は目標にwatchPosを置いてhunt。
  - fix: 射程8割の手前でguard、小さいleash。cutはhunt、reconはscout（既存の巡回点と高度も渡す）。
  - reserve・refit・retire: 拠点でguard、小さいleash。
  - 支援: 任務の拠点の味方側でguard。母艦はlaunchR内に置く。
- **台本との境界**: NPC有効時は装甲75%・50%によるsortieを使わない。増援は到着してから指揮官の隊に入る。要塞陥落後の`startChase()`以降は判断・適用を止め、従来の追撃に任せる。案内中はsortieも含め従来どおり。勝敗・時計・報酬は変更しない。`npcDebug()`は地上・宇宙の有効な軍を返す。
- **確認**: `tests/npc-space.cjs`（Nodeとsmoke）、`tools/npc-sim.cjs charybdis mars earth standard 1 900`（`--no-npc`で台本比較）。自軍は既存のautoAI。`tools/npc-measure.cjs`へNPCあり／なし・seed1〜2を追加。実測結果と未実行は状態メモで区別する。

頭に足りない入力・現状の境界（頭は変更しない）:

- 頭の状況には要塞の残存装甲・被弾の緊急度が無い。現在は観測した敵の接近から本営の脅威を判断する。装甲低下そのものを見た緊急の守備変更はできない。
- 頭の前進→突入は拠点半径による距離で判定する。宇宙の射程・高度や、実際の前進持ち場への到着は入力にないため、射程が長い隊や高度差の大きい作戦では段取りの精度に限界がある。
- 既存`pickFoe()`は候補が空になると、現在の攻撃目標を保持する場合がある（両スコアがInfinity）。NPCの宇宙守備だけ、任務変更時と毎ステップでleash外の攻撃命令を解除して持ち場へ戻す。候補を選ぶ共通AIは変更しない。
- このブランチの設計書には、作業票が参照する9.7節がまだない。型は既存の頭と`styles`データ（共和国既定mobile）をそのまま使用する。

## 9.7 作戦の意図と守り方の型（実装、数値は仮）

作戦データの `op.npc[軍].intent` を橋渡しが `sit.goal` へ渡す。省略時は `seize`。`type` は `seize`（取る）・`hold`（守る）・`delay`（時間を稼ぐ）・`withdraw`（逃がす）。`zones` は捨てない拠点のID、`until` は遅滞の期限（ゲーム秒）、`style` は守り方の型。

- `hold` と期限内の `delay` は力の比にかかわらず守りの姿勢。期限後は従来の力の比と反応遅れで姿勢を決める。期限省略の `delay` は守りを続ける。期限が近いほど拠点を手放しにくくする。
- 型は姿勢が `defend` / `delay` のときだけ適用。`withdraw` は遅滞型。それ以外は明示の `style` を優先し、未指定で姿勢が `delay` なら遅滞型、ほかは規範の既定（連合=固守、共和国=機動防御）。型の表を渡さない指揮官は従来の守りを使う。
- 捨てない拠点（must）は `zones` と本営。型の `abandon` による放棄の対象外。守備任務への割当は残る隊の力に制限される。

|型|守りと取り返し|
|---|---|
|固守 `firm`|指定拠点を厚く守り、失った必須拠点を取り返す。空いた拠点には出ない|
|遅滞 `delay`|前線だけを持ち、強い脅威で下がる。取り返しも空いた拠点の占領もしない|
|機動防御 `mobile`|守備を薄く予備を多く持つ。近い脅威に反応し、余力で取り返し・空いた拠点の占領を行う|
|縦深 `depth`|後ろの線にも守備を置く。二本以上の線が残る間に取り返し、必須拠点は線の数にかかわらず取り返す|

`withdraw` は姿勢 `delay` とし、前線ごとに殿を1隊残し、ほかを `retire` で `zones[0]`（未指定なら本営）へ退かせる設計。橋渡しは `retire` を通常の移動へ直し、到着後は待機させる。道路係には使わない。型が変わると `style:<型>` を log に残す。

確認は `tests/npc-core.cjs`（型・意図・切り替え）、`tests/npc-ground.cjs`（意図の入力と退避移動）、`tests/npc-sim.cjs`（引数と集計）。計測例:

```sh
node tools/npc-sim.cjs exercise2 earth mars standard 1 600 --intent0 seize --intent1 hold:firm:F,E --brief
node tools/npc-sim.cjs exercise2 earth mars standard 1 600 --intent0 seize --intent1 delay:delay:F:300 --brief
```

`--intent0` / `--intent1` は `type[:style[:拠点ID,拠点ID[:期限秒]]]`。省略欄は空文字にできる。`--brief` は `style:` の推移も出す。`tools/npc-measure.cjs` に演習場・seed 1・上限600秒の青攻撃／赤固守・機動防御・遅滞（期限300秒）・縦深の4条件を追加。赤の必須拠点は本営F、青の規範は連合、赤は共和国で統一する。決着時は早期終了する。数値は `docs/menu.md`「NPCの守り方の型の仮の値」。今回の実測結果は未記載。

固定状況の確認で見つかり、頭を直した問題（2026-11-11）:

- `withdraw` で前線に強い脅威が迫ると、放棄の判定が先に働いて殿が残らなかった。逃がすときは脅威の強さにかかわらず前線ごとに殿を1隊残す。
- 機動防御で始めた「空いた所を取る」任務が、`opportunism: false` の型へ切り替えても続いた。型が禁じたら出ていた隊も戻す。

## 9.8 輸送・上陸・架橋・補給（頭は2026-11-12、つなぎは実装 2026-11-14、Codex、レビュー前）

ユーザーの依頼（2026-11-12）で Claude（Fable 5.2）が設計した。バイコヌール演習では有効にせず、試験場で作る（ユーザー決定「バイコヌール演習ではなくて大丈夫」）。数値は仮で、表は `data/npc-doctrines.js` の `lift`。

考え方: 指揮官は戦場を拠点とつながりで見る。そこへ「今は通れないが、手段があれば通れるつながり」を足し、遠回り・架橋・海からを同じ経路探しの中で比べる。

### 頭への入力（橋渡しが作る）

- つながりの `way`: `'gap'`（橋のない川。`open:false` のあいだは工兵が架ければ通れる。架かったら `open:true` にする）、`'sea'`（海沿いの拠点どうし。揚陸艦で渡る）。どちらも、ふつうの距離と「隣」には数えない。
- 隊の `can`: `'bridge'`（工兵）、`'ferry'`（揚陸艦。`lift` は搭載上限の合計。空き数ではない（Claude決定2026-11-14）。搭載中の隊は同じ上陸任務へ結び付け、`busy:true` のまま残す）、`'supply'`（補給部隊）。
- 隊の `busy`: 任務の手順の途中（乗っている、架けている）で命令を受けられない隊。`free:false` でも任務から外さない。任務がなくなったら外れるので、橋渡しが降ろす・中止する。

### 頭の判断

- **経路**: 主攻の経路探しで、手段の要るつながりに上乗せ（川は `gap` km、海は `sea` km）を足して比べる。川は工兵がいるときだけ、海は味方の拠点から、揚陸艦で運べる力で取れる相手（敵の見積もり×攻める比 ≦ 運べる数×平均の隊）へだけ使える。連合は最短を選ぶので落ちた橋を架け直し、共和国は固い拠点を避けるので守りのない所から回る。
- **架橋**: 経路が川を渡るなら、任務 `bridge`（手前の拠点、`link`、`to`）を立てる。工兵1隊（`as:'work'`）と護衛（線・突破、平均1隊ぶん）を付ける。主攻は `via:'gap'`・`blocked` で、橋ができるまで集結のまま待つ（集結の時間切れでも出ない）。`gapMax` 秒で架からなければ中止し、そのつながりを `retry` のあいだ使わない。
- **上陸**: 主攻か遮断の任務に `via:'sea'`・`link` を付ける。主力は運べる隊の数まで。揚陸艦は `as:'lift'` で付く。集結（乗る拠点）→ 前進（乗って渡る）→ 突入（上陸して取る）。前進が `seaMax` 秒を超えたら中止し、その拠点とつながりをしばらく避ける。遮断は、海でつながっていれば前線を通らず海から回る。
- **補給**: 補給部隊は、主力の補給の減りの合計がいちばん大きい任務に `as:'supply'` で付く（攻めの任務は1.5倍に数える。合計が `supplyNeed` 以下ならどこにも付かず、今までどおり主攻の支援に回る）。主攻の補給の平均が `supplyGo` 未満なら、集結で `supplyWait` 秒まで待ってから出る（log に `seize:resupply`）。
- 任務の出力に `via`・`link`・`to`・`blocked` を足した。

### 橋渡しの仕事（実装 2026-11-14、Codex、レビュー前）

- 地形から、架けられる川（幅が工兵の上限以下で、両岸に足場がある所）を拠点のあいだの `gap` のつながりにし、架橋の地点を持っておく。海沿いの拠点どうしを `sea` のつながりにする。
- `bridge`: 護衛を手前の岸へ出し、建設位置に敵がいなくなってから工兵に架橋を命じる。
- 上陸: 集結で主力を浜へ、揚陸艦を岸へ。前進で乗艦し、目標の近くの浜へ渡る。敵が見えている浜には上陸しない。上陸中に敵が現れたら中止して沖へ戻る。揚陸艦が沈むと乗っている隊は全滅なので、見えている敵の射程を避けて渡る。
- 輸送車: 頭は判断しない。同じ任務の歩兵について、乗る場所から集結地点までの実際の残り経路が仮6 km以上のときだけ乗せる。直射が届く手前で降ろし、降車後は仮30秒乗り直さない（Claude決定2026-11-14）。
- 補給部隊: 付いた任務の主力の後ろ、配れる距離（1 km）の中で、見えている敵の直射が届かない所に止まる。自分の残りが減ると、頭の再編で補給の届く拠点へ戻る。

- 地形の海岸セルと隣接する車両の通れる浜を探し、拠点の中心から浜まで仮6 km以内なら沿岸とする。exercise2 はD・H・Gでsea 3本。gapは東分流のD–H 1本、地点は[24.2,11] km。地形と架橋上限0.3 kmは変更しない。
- 未開通のgapとseaは拠点間の直線距離で比べる。gapの開通後は、完成した橋を含む実際の地上経路長へ更新する。完成・破壊は `groundBridgeRevision` と実橋の状態から反映する。
- 初期搭載の揚陸艦が主攻の支援に付いた場合も、海でつながる同じ目標へ搭載隊を運ぶ。搭載隊を艦の割当任務へ結び付ける処理は橋渡しに置く。上陸完了後に同じ任務の出発地へ呼び戻さない。満載でviaが消える問題は搭載上限を渡すことで解消し、`npc-core.js` は変更していない。
- 演習 `groundLiftExercise` はhidden/debug/fixed。自軍本営はH、敵本営はD。敵地上隊は東分流の南側[24.2,11]付近から出す。頭が比べるD–Hは直線31.26 km＋架橋6 km＝37.26 km、既存道路45.45 kmより短い。既存作戦の初期配備と判断は変えない。
- 確認: `node tests/npc-lift.cjs`（npc組にも含む）、`node tools/npc-lift-check.cjs 1 2 3`（3seedの実ステップ、結果はtest-results、写真は.shots）、`node tools/npc-lift-regression.cjs`（HEADの橋渡しとの既存4作戦の60秒比較）。仮の数値は `docs/menu.md`。

### ユーザーが決めたこと（2026-11-12）

- 試験場はチュートリアル2の地形（`exercise2`。川・橋・海・浜がそろう）。チュートリアル2そのものは変えない。
- この地形で、敵が架橋や上陸を使ってくる遊べる演習を1つ足す（デバッグで開く）。
- 工兵の架けた橋を敵の砲兵が撃つ動きは、今回は入れない。

## 9.9 指揮官の調整（2026-11-14、バイコヌール演習の AI どうし）

ユーザーが「指揮官の数値の調整」の再開を選んだ。測ると、止まる原因は数値ではなく作りだった（`tools/npc-sim.cjs baikonur <0軍> <1軍> standard <seed> 600`、友軍分けあり・なし、seed 1〜3、8本）。

|原因|どう止まるか|直し|
|---|---|---|
|建物の中の隊が見えない|建物（約170m×150m の箱）の中に立つ隊は、外が見えず外からも見えない。E の町で両軍の歩兵が0.6kmで向き合ったまま撃たず、拠点が競合のまま300秒動かない|立てこもる形（ユーザー決定、`docs/spec.md`）|
|攻撃の命令が射程の内側で止まる|射線が切れていても射程の8割の内側では近づかない|撃てるまで近づく（ユーザー決定、`docs/spec.md`）|
|占領できる隊がいない主攻|歩兵が全滅すると、戦車1隊や攻撃機1隊を主力にして突入を続ける（216〜351秒）|占領の決まりの変更（ユーザー決定: 強化歩兵と W.A.S. 以外は2隊で占領）と、頭の割り当ての直し。別の作業票|
|測る道具の友軍分け|`--ally` で分けた先導の指揮官が自分の半分しか数えず、力の比が下がって守りに入る。資料の「150秒すぎに両軍とも守り」の多くはこれ|頭へ `sit.friendPower`（この指揮官が動かさない味方の力。力の比にだけ数える）。橋渡しは分けたときだけ渡す|

前の2つと道具を直したあと: E の膠着は消え、拠点の取り合いが増えた（例: 0軍=共和国 seed 2 は占領2回→4回）。残った長い突入は、どれも占領できる隊のいない主攻。本番と同じ組（0軍=連合、1軍=共和国の指揮官）では、共和国は44秒から攻め続け、棒立ちにはならない。連合の規範（攻め始める比 1.5）は、互角に近いと守りに入りやすい。今はプレイヤーの側なので直していない（友軍の指揮官に使うときに見る）。
