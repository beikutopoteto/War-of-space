# 資料の整理（/tidy-docs）

目的: 次のセッションが少ないトークンで正しく作業を始められるようにする。会話の中にしかない決定を資料へ移し、古い記述を直し、CLAUDE.md を短く保つ。

## 1. 今の状態を知る（読みすぎない）
- `npm run check-docs` を走らせる。CLAUDE.md の大きさ、資料に書いたファイルのリンク切れ、古い名前の残りがわかる。
- `docs/roadmap.md` の「現在地」と「最終整理」の行を読む。
- `git log --oneline <最終整理のコミット>..origin/main` で、前回の整理からマージされた PR を一覧にする。中身が必要な PR だけ `git show --stat` で見る。

## 2. 決まったことを移す
この会話でユーザーが決めたことと、Claude が置いた仮の値を、正しい場所へ移す。会話にしか残っていないものを優先する。
- ユーザーが決めた仕様 → `docs/spec.md`（日付つき。前の決定を変えたなら、古い記述を直し「〇〇から変更」と書く）
- 細かい操作、仮の数値 → `docs/menu.md`（「仮」と書く）
- 物語（人物、あらすじ、戦闘の流れ、会話）→ 章ごとの `docs/chapterN.md`。作戦の表と実装（編成、数値、仕組み）→ `docs/campaign.md`。章をまたぐ世界設定 → `docs/story.md`（`/story-draft` の置き場所の表と同じ）
- ユーザーの指示の読み方で新しくわかったこと（言い換え、範囲の絞り方、聞き返されたこと）→ `docs/requests.md`
- 進み具合 → `docs/roadmap.md` の「現在地」とフェーズのチェック。「ユーザーの判断」の表も更新する。
- 書かない: 試した手順の細かい経過、すでにコードやテストを見ればわかること、一度きりの質問への答え。

## 3. CLAUDE.md を短く保つ
- 7000 バイト以下（`npm run check-docs` が確かめる）。毎回読み込まれるので、全セッションで要ることだけを置く。
- 詳しい仕様、数値、経緯は docs/ へ移し、CLAUDE.md には「どこに何があるか」だけを残す。
- ファイルを足したり消したりしたら、CLAUDE.md の「資料」の表と「ファイルと動かし方」、`docs/code.md` を直す。コードの細かい構成は `docs/code.md` に置き、CLAUDE.md には要点だけ。

## 4. ほかの .md をそろえる
- `.claude/agents/wos-dev.md` と `.claude/skills/*/SKILL.md` が、今のファイル構成と手順に合っているか確かめる。
- `ship` の試遊ページの `files` の表が、`battle/` と `data/` のファイルと合っているか確かめる（`ls battle data`）。
- `README.md` のファイル一覧が古くないか確かめる。

## 5. 仕上げ
- `npm run check-docs` と `npm test` が通ることを確かめる。
- `docs/roadmap.md` の「最終整理」の行を、今日の日付と、整理の直前の `main` のコミットに更新する。
- `/ship` の手順で PR にしてマージする（資料だけなので試遊ページは載せ直さない）。
- ユーザーへ短く報告する。会話が長くなっていたら、「新しいセッションを始めると、溜まった会話を引き継がずに資料から軽く始められる」と添える。
