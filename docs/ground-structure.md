# 地上のコードの作りの見直し（第二章の前に）

2026-11-12、ユーザーの依頼で Claude（Fable 5.2）が見直した。第二章（`docs/chapter2.md`）を載せる前に、何を整理しておくかの判断。書き換えそのものは Codex か Opus に渡す。ここに書いた新しいファイル名はすべて仮。

## 1. 結論

第二章は、演習のほかに地上の作戦が6つある。作戦ごとに地図が違い、勝ち方が違い（遅滞、増援まで持ちこたえる、川で食い止める、二正面、上陸）、途中で出来事が起きる（増援、敵の降下、天候、W.A.S. の配備）。今の地上のコードは「地図1つ、出来事なし、勝ち方3種類」の演習のために作ってあり、このまま6つ載せると作戦ごとの特別扱いがコードに積み上がる。

先に整理するのは次の4つ。上から順にやる。

| 順 | 整理すること | 今のまま進めたときに困ること |
|---|---|---|
| 1 | 規則と地形を分ける | 地図を足すたびに規則の写しが増える。天候や作戦ごとの違いを置く場所がない |
| 2 | 作戦データの部隊の書き方を km にそろえる | 地図の大きさを作戦データの式に埋めている。増援や降下でも同じ式を書くことになる |
| 3 | 地上の「台本」を作る（出来事と勝敗をデータで書く） | 時間で起きる出来事が地上では動かない。勝ち方は3種類がコードに直書き |
| 4 | 地形の検査の道具を作る | 架けられない川、つながらない補給、色の違う隅を、遊んでから見つけている |

あわせて、テストを分野ごとに分ける（5.）。これはどの順番でもよく、早いほど得をする。

やらないと決めたこと: 宇宙と地上のコードを大きく2つに分ける書き換え（6.）。

## 2. 規則と地形を分ける

**今**: 兵科の表、戦闘、補給、占領、移動、輸送、上陸、工兵、視界、地点攻撃、高度の段の規則が、地形のファイル `data/terrain/exercise2.js` の中にある。`data/terrain/baikonur2.js` と `data/terrain/wide-fields.js` は、12個の規則を名前で並べて写している。自軍の地上編成（`data/ground-org.js`）は、隠し作戦 `groundExercise2` の部隊と `exercise2` の兵科の表を直接読んでいる。

**困ること**: 規則を1つ足すたびに、写しの一覧を全部の地図で直す（忘れると、その地図だけ規則が欠ける）。作戦ごとの違い（第5節まで W.A.S. なし、雨で視界と足が変わる）を書く場所がない。今日の「バイコヌールだけ架橋の上限を変える」は、たまたま地形の側の値だったので書けた。

**決めること**:

- 規則は1つのファイル（仮: 地上の規則のデータ）に置く。地形のファイルは地形だけ（地図の大きさ、標高、川、道、橋、拠点、森、建物）。
- 規則を読む入口を1つにする。順に重ねる: 基本の規則 → 地形の上書き（その土地だけの値。川幅の上限など）→ 作戦の上書き → 試合中の変化（天候）。今も `groundSupplyRules()` のような入口の関数を通っている所が多く、地形から直接読む所は約20か所なので、今なら小さい。
- 自軍の地上編成は、隠し作戦ではなく規則のデータから既定の編成を作る。

**大きさ**: 小〜中。動きは変えない。全部のテストが今のまま通ることで確かめる。

## 3. 作戦データの部隊の書き方

**今**: 作戦データ（`data/operations.js`）は、部隊の位置を `pos:[(x-24)*4,(18-y)*4]` のような式で書く。24 と 18 は地図の半分の大きさ、4 は画面の縮尺で、96 km の地図用に別の関数がある。地上の部隊は、宇宙の艦隊のふりをしている（`type:'cv',n:1,scale:.3`）。道具とテストの約20ファイルも同じ式を持っている。

**困ること**: 地図ごとに式が要る。増援や降下（次の節の台本）で出す部隊も同じ書き方になるので、先にそろえないと式がさらに広がる。

**決めること**: 作戦データでは、部隊を「名前・兵科・km の位置・高度の段」だけで書く。画面の座標と艦隊の形へ直すのは、地上の側で1か所。早送りの道具とテストも、同じ入口を使う。

**大きさ**: 中。次の節の台本と同じ PR にまとめてよい。

## 4. 地上の台本（出来事と勝敗）

**今**: `battle/sim.js` の1ステップは、地上なら初めに `groundStep()` を呼んで戻る。宇宙の出来事の仕組み（時刻で増援・通信・段階の切り替え）は、その先にあるので地上では動かない。地上の勝ち方は `battle/ground.js` に3種類（全拠点の占拠、敵本営の占領か全滅、案内の完了）が直書きで、負けは自軍の全滅だけ。

**第二章で要るもの**（`docs/chapter2.md` の各節から）:

| 節 | 要る出来事と勝敗 |
|---|---|
| 1 中東・遅滞 | 敵の増援が次々に着く。決めた時刻まで持つ、または決めた数の隊を出口へ逃がせば勝ち |
| 2 中東・防衛 | 友軍の増援が時刻に着く。それまで本営を守れば勝ち |
| 3 華南・川 | 敵の波。橋と川の線を時刻まで保つ |
| 4 広州前面 | 敵が後ろへ降下する（予告つきで空から出る）。前と後ろの二正面 |
| 5 広州 | 守り切る。終わりに W.A.S. が配備される |
| 6 海岸・上陸 | 上陸、海戦、艦砲。拠点を取り、敵を逃がさない |

**決めること**: 地上専用の小さな台本の層を作る（仮: 地上の台本のファイル。`battle/sim.js` の出来事の処理へ地上を戻すのではなく、地上の側に置く）。作戦データに次の3つを書く。

- **きっかけ**: 時刻、拠点の持ち主が変わった、拠点を失った、ある軍の力が割合を切った、ある軍が円に入った、旗が立った、別の出来事の何秒後。`all`（全部）と `any`（どれか）で組める。
- **すること**: 部隊を出す（地図の端から、空から降下、海から。出た隊は指揮官に入る）、通信を出す、目標の文と勝敗の条件を変える、指揮官の意図を変える（`docs/npc-doctrine.md` 9.7 の seize・hold・delay・withdraw）、拠点の持ち主を変える、天候を変える、旗を立てる、地図に印を出す、出口を開く、勝ち・負けで終える。
- **勝ちと負けの条件**: きっかけと同じ部品で書く。足す部品は、拠点を時刻まで保つ、決めた数の隊が出口から出た、ある軍が全滅した、時刻になった。今の3種類の勝ち方も、この部品で書き直す。

宇宙の出来事の書き方（`after` 分、通信の `log`）と言葉をそろえるが、コードは共有しない。宇宙の出来事は作戦ごとの特別扱いが多く、地上を合流させると両方が壊れやすくなる。

**大きさ**: 中〜大。部品の一覧（上の3つ）を先に資料で固め、演習1つ（増援と降下と時刻の勝ち）で試してから第二章へ進む。ここが6つの作戦すべての土台になる。

## 5. 地形の検査の道具とテストの分け方

**地形**: 地図は3つあり、作り方が3通り（値を直書き、規則を写して組み立て、生成）。第二章であと6つ要る。作る手順はそのままでよいが、できた地図を検査する道具を1つ作る。見るもの:

- 拠点が道路に載っている、両軍の本営が道路でつながる、橋が川の上にある
- 兵科ごとに、本営から本営まで通れる道がある
- 工兵が架けられる所と、揚陸艦が着ける浜が、どこにどれだけあるか（一覧で出す）
- 盤の端と海の塗りに、地面の色が出ていない
- 重さ: 経路探索と視界の1回の時間が、決めた上限に入る

今日ユーザーが遊んで見つけた3つ（上の方の川に架けられない、補給がつながらない、南の隅が陸地）は、この検査で先に分かる種類のもの。

**テスト**: 今は `tests/smoke.cjs` が37ファイルを1本で回し、CI は約17分かかる。宇宙・地上・NPC の3つに分けて並べて走らせ、手元では分野を選んで走らせられるようにする。どの PR も待ちが短くなるので、早くやるほど得をする。地上の作りには触らない。

## 6. やらないこと、後でよいこと

- **宇宙と地上を大きく2つに分ける書き換えは、しない。** 共通の本体（`battle/sim.js`）と地上の分かれ目は、ステップ・視界・移動・損害・表示の14か所だけで、すでに細い。地上は初めに自分の処理へ抜ける。ここを書き換えても第二章は楽にならない。
- **画面のコード**（`battle/hud.js` に34か所、`battle/state.js` に30か所の地上の分かれ目）は、今は分けない。第二章で増える画面は少ない（天候の表示、降下の予告）。決まりを1つだけ置く: 地上の新しい画面は地上のファイルに書き、共通の2つに分かれ目を足さない。
- **`battle/ground.js`**（勝敗、占領、部隊の一覧、表示、ステップが一緒）は、台本を作ると勝敗がそちらへ移り、そのぶん軽くなる。残りは触るときに分ける。
- **部隊の状態**（部隊に付く地上用の値が53種類）は、今は困っていない。やり直しや出来事で部隊を出すときの初期化だけ、台本を作るときに1か所にまとめる。
- **重さ**: バイコヌール演習（96×72 km）で1ステップ平均4ミリ秒。第二章の地図はこの大きさを上限の目安にし、もっと広くするときに測り直す。

## 7. ユーザーに決めてほしいこと

1. **第二章の自軍の部隊**: 作戦ごとに決まった部隊で戦うか、プレイヤーが編成した部隊を持ち込むか。損害を次の節へ持ち越すか。これで、編成の画面と台本の「部隊を出す」の作りが変わる。Claude の案: 第一章と同じく作戦ごとに決まった部隊を基本にし、編成の持ち込みは第二章のあとで考える。
2. **進める順番**: 1. の表の順（規則 → 部隊の書き方と台本 → 地形の検査）でよいか。輸送・上陸・架橋を使う敵（`docs/npc-doctrine.md` 9.8 のつなぎ）は、部隊の書き方をそろえたあとに入れると書き直しが少ない。
3. **誰が書くか**: Codex は使用量の上限で 2026-11-16 まで使えない。待つか、Opus が書くか。
